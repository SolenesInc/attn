# Prove it works

Apply before reporting any change complete.

Before reporting a change complete, check the real thing on the surface the change affects: the command, the running product, the stored value, or the trace. Do not accept a proxy such as a green build or your own account of the work. Script the check when you can, so a reviewer reruns the check instead of trusting you. When a check disagrees with what you expect, suspect the way you observed before you suspect the system.

A check that could not run is inconclusive, not a pass. Say so. Label each claim in a report as measured, inferred, or guessed. A claim is measured when you observed it in a run, inferred when the code implies it, and guessed when neither applies. Never hand the user a check you could run yourself.
