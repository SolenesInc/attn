# Prove it works

Apply before reporting any change complete.

Before reporting a change complete, check the real thing on the surface the change affects, the command, the running product, the stored value, the trace, rather than a proxy such as a green build or your own account of the work. Script the check when you can, so a reviewer reruns it instead of trusting you. When a check disagrees with what you expect, suspect the way you observed before the system. A check that could not run is inconclusive, which is not a pass; say so. Label each claim in a report as measured, inferred or guessed: measured when you observed it in a run, inferred when the code implies it, guessed when neither. Never hand the user a check you could run yourself.
