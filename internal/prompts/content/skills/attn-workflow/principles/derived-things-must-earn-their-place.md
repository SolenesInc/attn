# Derived things must earn their place

Apply before adding something derived from the work: documentation, a code comment, a summary, a generated file, or a copy of state.

The work is the truth. Anything derived from it goes stale when the work changes: documentation, code comments, summaries, generated files, copies of state. Before adding one, ask whether it is valuable enough to exist, and look for a better option that removes the need: clearer names or structure in the work itself, a pointer to the source, or deriving it when it's needed. Add it only when no better option exists, and then with a way to keep it current, as [Derived things](../references/derived-things.md) describes.
