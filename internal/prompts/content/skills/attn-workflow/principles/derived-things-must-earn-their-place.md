# Derived things must earn their place

Apply before adding something derived from the work: documentation, a code comment, a summary, a generated file, or a copy of state.

The work is the truth. Anything derived from the work becomes out of date when the work changes: documentation, code comments, summaries, generated files, copies of state. Before you add one, ask whether the thing is worth having, and look for a better option that removes the need: clearer names or structure in the work itself, a pointer to the source, or deriving the thing when someone needs it. Add the thing only when no better option exists, and add it with a way to keep it current, as [Derived things](../references/derived-things.md) describes.
