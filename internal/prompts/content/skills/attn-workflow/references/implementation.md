# Implementation

Read the agreed brief or plan and inspect the relevant code before editing. Make the change fit the codebase and resolve routine implementation choices yourself.

The plan's findings record what spikes and investigation already established. Build on them rather than rediscovering them. When the code appears to contradict a finding, or a simpler route appears than a finding allows, treat it as an unforeseen issue below instead of working around the finding.

A change that turns out to need a parallel version of an existing mechanism, which the plan did not account for, is an unforeseen issue. So is a departure from the plan's Design, such as a parameter, type or owner it did not anticipate: decide whether the design was wrong, a requirement was missed, or the implementation is overreaching, instead of absorbing the difference silently. When an unforeseen issue requires a consequential decision, bring the evidence, what you tried, and your recommendation to the coordinating agent identified in the brief, or to the user if none is identified. Continue independent work while waiting; wait before proceeding with work that depends on that decision.

Verify the affected behavior as the skill's engineering judgment describes under prove it works and sequence verifiable units: each unit ends in a check you ran on the surface the change touches, following the repository's verification guidance. Reuse evidence that still applies and run further checks where changes or gaps warrant them. Address review findings, then verify the corrections. When two corrections that shared an assumption have failed the same check, attack the premise as the skill's engineering judgment describes before writing a third.

Return a reviewable change with the revision, each completion check from the brief or plan with the current evidence that proves it, how to rerun the checks, and remaining limits. When a later run replaces evidence, point the check at the new evidence and name the artifacts it supersedes in the same note, so a reviewer never has to work out which of several reports is current. Leave earlier artifacts attached: the plan and notes may cite them. Make the result readable in the conversation and durable in the seed. Follow the task's authorization for delivery steps.
