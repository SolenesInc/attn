# Plan: tendril, a sandboxed Go subset for scripts

Status: design and spike. The spike lives uncommitted in `internal/tendril`:
about 4,400 lines of code, 400 of them per-kind operator dispatch, plus
1,200 lines of tests and conformance corpus.

## Summary

Tendril is a subset of Go that attn compiles and runs inside the daemon. A
script is a Go source file. The standard library's `go/parser` and `go/types`
are the whole frontend. Tendril adds three things: a compiler from the typed
syntax tree to closures, a meter, and a host boundary that gives a script only
the functions the host hands it.

```go
import (
	"attn"
	"fmt"
	"path"
	"strings"
)

func Gate(pr attn.PullRequestInput) (attn.Verdict, error) {
	if pr.Draft {
		return attn.Verdict{Skip: "draft"}, nil
	}
	files, err := attn.ChangedFiles(pr.Owner+"/"+pr.Repository, pr.Number)
	if err != nil {
		return attn.Verdict{}, fmt.Errorf("listing files: %w", err)
	}
	for _, f := range files {
		if ok, _ := path.Match("internal/pty/*", f); ok {
			return attn.Verdict{Launch: true, Prompt: "Review " + pr.URL + " with care for " + f}, nil
		}
	}
	return attn.Verdict{Skip: strings.Join(files, ",")}, nil
}
```

```go
	tendril.NewPackage("attn").

```

Why Go and not a new syntax:

- The agents attn runs write Go well, and so does its maintainer. A new
  syntax would be one more thing both get wrong.
- Scripts are ordinary Go files, so gofmt formats them and editors highlight
  them. With a generated stub package, gopls checks them too.
- `go/types` reports type errors before a run, with positions and Go's own
  messages. It folds constants, orders package initialization, and resolves
  every identifier, so the compiler does no name lookup at run time.
- Go is the reference implementation. A conformance test runs each corpus
  program through both `go run` and tendril, and requires byte-identical
  output.
- It adds no dependencies. The parser and type checker are standard library.

## The promises

1. **No ambient authority.** A script reaches only the packages its `Env`
   declares. It has no `os`, `net`, `unsafe`, `reflect`, goroutines or
   channels, and no `print`, which would write to the daemon's stderr. Every
   import resolves through the `Env`. An unknown path fails to compile:
   `package "os" is not available to scripts`.
2. **Bounded.** Four limits are checked by the interpreter, not by the
   script's cooperation:
   - fuel: statements, loop iterations, calls, and work proportional to the
     input of builtins and host calls;
   - an allocation budget;
   - call depth, which also guards the Go stack, since a Go stack overflow
     cannot be recovered;
   - the caller's context.

   A halt is latched on the machine. Host code that recovers panics cannot
   swallow it. `fmt` recovers panics from `String` methods, so this case is
   real.
3. **Contained.** Script runtime errors, panics and host-function panics
   come back as errors with the script position, for example
   `gate.go:14:2: runtime error: index out of range [5] with length 2`. The
   daemon never crashes.
4. **Deterministic.** The same program, inputs and host results give the
   same output and the same fuel count. Scripts cannot read a clock or a
   random source unless the host provides one. Ranging over a map visits
   keys in sorted order, which is one of the orders Go allows, so a script
   is still a correct Go program.
5. **Isolated.** Values are copied across the boundary in both directions,
   so a script cannot mutate host memory. Each run gets fresh globals. A
   compiled `Program` is immutable and is shared safely across goroutines.
6. **Cheap at rest.** A compiled program holds about 12 KB. It owns no
   goroutines, timers or caches, so it costs nothing while idle.

## Where it fits in attn

An abstraction needs a current requirement. These are the candidates I found,
strongest first.

- **Automations.** Today a trigger's repository filter matches exact names,
  and the prompt is static text. A gate script would decide whether an
  occurrence starts a run and compose its prompt. Inputs would be paths
  changed, labels, the author, or the time. The spike's example uses the real
  `automation.PullRequestInput` as the script's type.
- **Orchestration.** This is the role the goja workflow engine plays. The
  glossary marks that engine for removal. If attn keeps script-driven
  orchestration, tendril fits it better than goja:
  - determinism by construction instead of bans on `Date` and `Math.random`;
  - a memory limit, which goja lacks;
  - fuel and context checks instead of a watchdog that interrupts the VM;
  - replay keyed by call sequence instead of call-site ordinals and path
    stacks;
  - about 3 MB of binary instead of about 9 MB.
- **Small plugin hooks**, such as `worktree.before_create`, without
  starting a bun process. Plugins that hold a long-lived connection stay
  out of process.

Not a fit:

- The classifier: CLAUDE.md rules out heuristics there.
- Auto-mode rules: pi evaluates those in TypeScript.

Proposal: land tendril only together with its first consumer, the
automation gate, behind an experimental setting.

## Language

Supported:

- Types: booleans, every integer and float kind, and strings. Also slices,
  maps keyed by booleans, numbers or strings, structs, and pointers to
  structs.
- Functions and closures. Closures capture by reference and keep Go 1.22's
  per-iteration loop variables.
- Methods with value and pointer receivers, interfaces, type switches, type
  assertions, `error`, and multiple results with named results.
- Variadic functions, constants with `iota`, and package-level variables
  with dependency-ordered initialization.
- `if`, every form of `for` and `range` (including range over an int),
  `switch`, `break` and `continue`.
- The builtins `len`, `cap`, `append`, `make`, `new`, `delete`, `copy`,
  `clear`, `min`, `max` and `panic`.

Left out, with the reason:

| Feature | Why |
|---|---|
| goroutines, channels, `select` | Concurrency belongs to the host, as a host function such as `agents.Parallel`. |
| `print`, `println` | They write to the daemon's stderr. |
| `defer`, `recover` | A script holds no resources, and a runtime error ends the run. |
| `&x` on a variable, pointers to non-structs | They keep the value model small. `&T{}` and `new(T)` work. |
| arrays, complex numbers, embedding, method values | Spike scope; none is hard. |
| labels, `goto`, `fallthrough`, generic declarations | Spike scope. Generic host functions such as `slices.Sort` work. |

Each is refused at compile time with a positioned message.

Deviations from Go:

- Map range order is sorted.
- A nested pointer prints as `&{...}` rather than as an address, which would
  not be deterministic.
- The package clause is optional for one-file scripts.

## Host boundary

- **An `Env` is the sandbox.** It holds packages. A package is a path plus Go
  functions, types and constants, registered as real Go values. Reflection
  turns their signatures into `go/types` objects, so the host's Go types are
  the script's types. One declaration both checks the script and calls the
  host.
- **Capabilities are functions; entities are ids.** A script holds no host
  object. It passes an id to a function. This matches the bus rule that facts
  carry entity ids.
- **Context and billing.** A host function whose first parameter is
  `context.Context` gets the run's context, which the script never sees.
  `tendril.Charge` and `tendril.Burn` bill the run for the work done.
- **Errors keep their identity.** A Go error from a host function can be
  wrapped by the script with `%w`. Back on the host, `errors.Is` still finds
  the original.
- **The prelude** (`tendril.Std`) is a curated part of `strings`, `strconv`,
  `fmt`, `errors`, `regexp`, `path`, `math` and `slices`. Functions that can
  amplify allocation are wrapped to charge their worst case before running:
  `strings.Repeat`, `strings.ReplaceAll`, and `fmt` padding. Regular
  expressions are RE2, so matching takes linear time.

## Durability

A host package marked `Journaled` records each call's function, argument
digest and results, in call order. `Program.Resume` runs the script again
from the start and answers the recorded calls from the journal. Finished
agent runs come back at once, and live calls pick up where the journal ends.
If the script was edited and its calls no longer match, the run fails with
`ErrDiverged` instead of replaying stale results. Nothing else in a script
can observe the outside world, so replay is sound without bans.

Still open:

- serializing journal results through the host types;
- where the journal is stored;
- whether a long call should suspend the run instead of blocking it.

## Spike results

Measured on a 4-vCPU Xeon at 2.8 GHz with Go 1.27.1.

Conformance and safety:

- **Conformance.** Six corpus programs (basics, closures, structs,
  interfaces, collections, control) produce output byte-identical to
  `go run`.
- **Sandbox suite.** All 14 hostile scripts halt with the right limit: empty
  and busy loops, runaway and mutual recursion, string doubling,
  `make([]int, 1<<40)`, unbounded append, map and closure growth, a
  `strings.Repeat` bomb, `ReplaceAll` amplification, `Sprintf` padding, and
  halts raised inside `Error` and `String` methods that `fmt` calls. A
  50 ms deadline stops a run with unlimited fuel. The suite passes under
  `-race`, with 16 concurrent runs of one program giving identical output
  and fuel.

Speed (time and allocations per run):

| Workload | tendril | goja | native Go |
|---|---|---|---|
| `fib(20)`, recursive | 1.6 ms, 64 allocs | 4.1 ms, 39 allocs | 0.04 ms |
| 100k-iteration arithmetic loop | 13 ms, 233k allocs | 24 ms, 200k allocs | — |
| word count, sort and join (3.7 KB of text) | 0.58 ms | 2.0 ms | — |
| review gate: compile | 0.23 ms, 67 KB | — | — |
| review gate: call | 25 µs, 5 KB | — | — |

Cost:

| Cost | Value |
|---|---|
| fuel rate | about 5 ns per empty loop iteration, about 18 ns per simple statement |
| `DefaultLimits.Fuel` (10M) | at most about 0.05–0.2 s of CPU |
| stripped binary over a 1.5 MB baseline | tendril +2.8 MB, goja +8.9 MB |
| memory a compiled program holds | about 12 KB (review gate) |

The 233k allocations in the loop come from ints larger than 255 being boxed
in `any`. The fix is in the next steps.

## Next steps

1. **Typed closures.** Specialize int, float and bool expressions so they
   stop boxing. This is the main remaining speed and allocation lever.
2. **Fill in the language.** Arrays, labels, embedding and method values,
   each checked against `go run` by adding to the conformance corpus.
3. **Differential fuzzing.** Generate Go programs and compare tendril with
   `go run`.
4. **Editor support.** `attn script stubs` writes the `Env` as a Go module
   that gopls can load.
5. **Storage and authorship.** Where scripts live (an automation's
   definition file, a repo's `.attn/`), and who may change them. Agents
   would propose and the user would promote, as with auto-mode rules.
6. **Journal persistence** for the orchestration case, if attn keeps it.

## Decisions needed

- The first consumer. Proposed: the automation gate.
- Whether orchestration stays in attn. If it does, tendril replaces goja;
  otherwise the workflow engine is removed as planned.
- The name.

## Alternatives considered

| Option | Why not |
|---|---|
| goja (already a dependency) | JavaScript. Needs determinism bans, has no memory limit, adds about 9 MB, and has no static types. |
| Starlark (`go.starlark.net`) | A strong, proven sandbox, but Python-flavored, dynamically typed, without a memory limit, and a new dependency. |
| Yaegi | Full Go, but not a sandbox: no fuel, it allows goroutines, and its stdlib symbols reach the host. |
| expr, CEL | Expressions only. CEL's cost limits are good for predicates, but it cannot express a gate that calls a capability and branches. |
| Wasm (wazero) | The strongest isolation, but scripts need an ahead-of-time toolchain, so they are not dynamic. |
