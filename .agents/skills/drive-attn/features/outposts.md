# Outposts

Agents and terminals on other machines, driven from the home's app. An
outpost is another computer running the same attn build, such as a Linux box,
that the home connects to over an SSH bridge. Shells, Claude Code, Codex and
Sigma on an outpost appear in tiles beside local ones, and their state, turns, cost and
pull request links reach the home. The user adds, re-pairs, updates and
removes outposts in Settings. Agents open shells and delegate onto them with
`--host`. Outposts are experimental and off by default.

## Sub-features

- `outposts-switch`: Outposts on or off at the home. Off keeps the list and makes every outpost terminal offline.
- `bridge-socket`: every daemon accepts its user's bridge connections on its local bridge socket.
- `outpost-pair`: add an outpost by ssh destination, with an optional name. The home pins the outpost's host key and daemon id on the first connection.
- `bridge-states`: connecting, connected, stalled, lost and refused, with the last error.
- `outpost-connect-terminal`: answer ssh prompts in a focused home terminal. After ssh succeeds, the home reconnects automatically, and the user closes the tile.
- `outpost-repair`: Re-pair makes the home forget the pins and connect again.
- `outpost-remove`: Remove makes the home close the outpost's terminals in every profile, release the enrollment, stop the outpost's daemon over ssh, and then forget the outpost. The outpost's files stay. An outpost enrolled to another home keeps that enrollment and its daemon.
- `outpost-update`: use the banner or the row to install the home's Linux build, `attn` and `attn-pty-host`, over ssh. Updating works even when a failed first Add left no build. On an outpost at the home's build without `attn-pty-host`, Add installs the host. A paired row carries `host_missing`, reads "Shared terminal host: Not installed" and offers "Install shared terminal host". Until then a new terminal on it fails with an error that says to update the outpost from its home.
- `enrollment`: an outpost's data folder belongs to the home it first accepted, until `attn enrollment leave`.
- `remote-terminals`: shells and agents on an outpost in tiles beside local ones. Their attn commands reach the home.
- `remote-tools`: with `agent_tools_enabled` on at the home, Claude Code on an outpost gets the outpost's own `/mcp`, with a credential the outpost's agent key signs. A `home` command runs at the home as the outpost session, a `here` command such as `seed_guide` runs on the outpost, and paths, evidence files and commits resolve in the session's folder on the outpost. With the bridge down a `home` command is refused with `home_unreachable: <home> is unreachable; this needs it now` and a Fix to call again. The home and other outposts refuse the credential with 401. The outpost's daemon log has the `agent tools:` line for each command, with the session it acted as; the home logs none.
- `offline`: a terminal whose outpost is unreachable stays in place, marked, and sends no typing.
- `ledger-resume`: a closed outpost session's ledger row names the outpost, and resume brings the session back on that outpost with its conversation and cost. For the ledger itself, see [ledger.md](ledger.md).
- `garden-resume`: a seed whose closed session ran on an outpost offers Resume on its page and in `attn seed show`, and resumes on that outpost. Reads never call the outpost; the press checks there and refuses naming what is gone. An unreachable outpost shows as unreachable, not missing. For the page, see [delegation.md](delegation.md).
- `markdown-tiles`: `attn open` from an outpost agent, and a markdown file it sends, open a markdown tile that the outpost reads and watches; the home asks again only when the outpost reports a change. Its images load from the outpost. Its annotations, and the files the outpost's agents send or edit in recent files and ⌘P, keep the outpost as their host. See [markdown.md](markdown.md).
- `launcher-reads`: `browse_directory`, `inspect_path`, `get_repo_info`, `create_worktree` and `delete_worktree` with `host` run on that outpost, and `agent_catalog` returns its harnesses. Before an outpost removes a worktree, whether by a delete or by the sweep, it asks the home. The home's open seeds keep the worktree's branch and get the removal note, and the home closes the sessions in that worktree. Without the home, the outpost refuses the removal. The sweep on an outpost also reads the home's open seeds before it decides, so it keeps a worktree a home seed owns, and without the home it decides nothing. Launcher 2.0 sends `host` for a recent on an outpost and for a typed machine path.
- `launcher-machines`: with an outpost attached, Launcher 2.0 lists recents from every machine with a machine badge. An outpost's recents show `~/…` for the home directory it reported when it last connected, also while it is lost. Enter, Tab's where list, ⌘Enter and ⌘⌫ act on the row's machine. The harness strip offers every harness installed on any machine. A start on an unreachable machine, or with a harness the target machine lacks, is refused in the dialog. A start on a stalled machine waits, and Esc leaves it to finish in the background.
- `launcher-addresses`: Launcher 2.0 reads `<machine>:<rest>` as a machine path. `ai-sandbox:~/` browses ai-sandbox, `ai-sandbox:attn` searches recents and aims them at ai-sandbox after it confirms the folder, and no prefix (or `home:`) means This Mac. An outpost's id also works, and `home:` names the home even beside an outpost named `home`. A name two machines share, the home included, lists both, completing a picked outpost by its id and the home by `home:`. Typing a machine's name offers it, and Tab completes `<name>:~/`. While an outpost is browsed, a status line says it is asking, the folder is missing, or the machine is unreachable. A folder missing on the target lists the other machines that have it. Opening prefetches each reachable outpost's home folder and its recents' parent folders, for that opening only.
- `notebook-sync`: the home and its outposts keep one notebook in sync, and the outpost's row shows the sync. For the notebook itself, see [notebook.md](notebook.md).
- `home-move`: with `remote_home_enabled` on, the home moves to a connected outpost and the old home becomes its outpost, keeping every terminal's process and screen. Pre-flight checks name each cause and change nothing. A daemon killed before commit leaves both machines as they were; one killed during commit is finished by running the move again. Rollback undoes a move until the old home has bridged to the new home (step `done`). On Linux the new home gets a systemd user unit that runs it with no app and no bridge. User docs: `docs/guide/reference/remote-home.md`.

## How to get to it

### People

- **Settings → Experimental** and the head of **Settings → Machines**: the Outposts switch, `settings.feature.outposts_enabled` (`native/crates/attn-app/src/settings/machines.rs`). Opening Settings is [settings.md](settings.md).
- **Settings → Machines** (`native/crates/attn-app/src/settings/machines.rs`): one row per machine, the home's first (`settings.machine.home`), then this machine, then each outpost (`settings.machine.<id>`). A row shows its home tag, its state tag and one status line. The list holds the keyboard: the arrows or j and k choose a row, M makes it the home, U updates it and D opens its details. Only the chosen row shows its buttons: "Make home", "Update" or "Install shared terminal host", "Update without it" after a failed update run, "Connect in a terminal" for ssh authentication and host-key refusals, "Re-pair" (not for a machine that dials the home), "Remove" and "Details". "Remove" shows a prompt reading "Remove and close N terminals" or "Remove and forget N terminals" with Cancel while the outpost has terminals. Details (`.details`) show the ssh destination, since, build, daemon id, host key, last error and notebook sync. The "Add a machine" form has an optional Name and the required ssh destination.
- The Outpost updates band under the title bar, `outpost-updates`, with its "Update outposts" button and its dismiss button (`native/crates/attn-app/src/outpost_updates.rs`). Dismissing hides the banner until the home build changes. After a successful update, the banner counts down from 5 seconds and closes itself. Hovering pauses the countdown. A later update shows the banner again.
- Where people see and steer what runs there: an outpost terminal's tile header shows the outpost's name on its second line, as a short mark on a narrow tile (`ai-sandbox` reads `as`) and never hidden while the outpost is unreachable, and the tile's strip says "<name> not responding" while stalled, "Connecting to <name> · typing is not sent" while connecting, or "<name> unreachable · typing is not sent" while offline (`native/crates/attn-app/src/desktop/host.rs`, `native/crates/attn-app/src/desktop/view.rs`). An unreachable agent is marked offline in the tile header, sidebar, queue, Home and palette. ⌘D (`terminal.splitVertical`) in an outpost shell opens another shell on the same outpost. A closed outpost session's row in the Sessions ledger shows the outpost's name, and the row's "Reopen" resumes the session on that outpost (`native/crates/attn-app/src/ledger/`). For the ledger itself, see [ledger.md](ledger.md).
- Launcher 2.0 (`native/crates/attn-app/src/launcher/`), whose keys start `new-session.`: each recent row carries its machine's badge, `new-session.row.<i>.machine`, and a row on an unreachable machine is dimmed. A harness missing on the highlighted row's machine is described as "<Harness> is not installed on <machine>". While the home checks for a harness, the harness has the "Checking for <Harness> on this machine" description and its checking mark, only on a row at the home. Typing a machine's name shows a row under "Browse a machine", and a folder found on another machine shows under "Found elsewhere". The line under the field is `new-session.status`.
- **Settings → Machines**, with `remote_home_enabled` on: a connected row's "Make home" (`settings.machine.<id>.move`, or M) runs the checks and lists them under the row (`.move.checks.passed`, `.move.check.<name>`), with the Notebook paths that change (`.move.path.<i>`), the crew homes that move with them (`.move.crew`) and, for a Mac, "While <machine> sleeps, the home is down." (`.move.sleeps`). "Move home to <machine>" (`.move.go`), "Check again" and "Cancel" follow; a failure shows as `.move.failed`. While the move runs, the row lists its six steps (`.move.step.<n>`) (`native/crates/attn-app/src/settings/machines.rs`).
- The move's band, `home-move`, over the window: "Moving home to <machine>" with "<n>/6 <step>", then "Home moved to <machine>." with a dismiss button. On the old home after a move whose new home never started: "Move failed: <machine>'s home didn't start." with "Roll back" (`home-move.roll-back`), then "Rolling back" and "Rolled back. The home is on this Mac." The **Can't reach** screen offers the same rollback (`connection.home-unreachable.roll-back`, `native/crates/attn-app/src/connection.rs`).
- On a machine that dials its home, the home away: the `connection` band says "Lost <home>" or "<home> refused this machine: <reason>" with Retry (`connection.home-lost`), and the **Can't reach** screen says the same (`connection.home-unreachable`, `native/crates/attn-app/src/connection.rs`). When the home refuses the machine's build (`home_unreachable`'s `refusal` is `build`) and the `update-run` band shows the machine's update of the home, such as "<home> runs another build." with Update, the `connection` band is hidden and the `update-run` band is the only one. **Can't reach** then leaves out the refusal's daemon ids, and `outpost_last_error` still holds them.
- Their own shell: on the home, run `attn settings set outposts_enabled true`. On the outpost, run `attn settings list --all` for `outpost_state`, `outpost_home` and `outpost_last_error`, and use `attn enrollment`, below. Setup is in `docs/guide/reference/using-outposts.md`.

### Agents

- `attn terminal open --host <outpost|home>` opens a shell on that machine at the end of the row (`cli/attn/src/commands/terminal/mod.rs`). For the verb itself, see [terminals.md](terminals.md). An agent on an outpost opens on its own machine by default, and `--host home` reaches the home.
- `attn delegate --host <outpost|home>` starts a delegate on that machine, and that machine checks the folder, refs and worktree. For the verb itself, see [delegation.md](delegation.md).
- `attn session reopen <id>` resumes a closed outpost session on the outpost it ran on, and refuses naming the host while that outpost is unreachable or removed (`internal/daemon/commands_session.go`). For the verb itself, see [ledger.md](ledger.md).
- `attn enrollment status` and `attn enrollment leave [--home <home-id>]` (`cli/attn/src/commands/enrollment.rs`). Run them on an outpost to see or release the home that outpost is enrolled to. With `--home`, the outpost keeps an enrollment to any other home, and the status reads `kept`.
- `attn home move [--check] [--via <ssh-destination>] [--json] <machine>`, `attn home status` and `attn home rollback` (`cli/attn/src/commands/home.rs`, `internal/daemon/home_move.go`). The move runs on the home; status and rollback run on the machine you call them on.
- An agent on an outpost runs every other attn verb through its outpost daemon, which reaches the home. When the home is unreachable, the command fails at once and names the home.

### Triggers

- The home dials each outpost, holds the bridge with heartbeats every 0.5 seconds, marks it stalled after 3 seconds of silence and lost after 60, and redials (`internal/daemon/outposts.go`, `internal/bridge`).
- With `self_update_enabled` on, an update run stages each reachable outpost before the home restarts and switches it afterwards. The Update run banner and the outpost's row show each outpost, and a staging failure offers **Update without it** (`internal/daemon/update_outposts.go`).
- After a new home build, the banner offers to update every outpost on a different build. Update builds or downloads, sends, verifies and reconnects on the home's build (`internal/daemon/outpost_update.go`). Outposts on one platform that update at once wait on one build instead of each making their own (`internal/outpostbuild/acquire.go`). The Outpost updates banner and the Update run banner name the outposts at the same step together.
- At start, before it opens its database, a daemon applies or rolls back the move its `home-move/<id>/move.json` records (`internal/homemove`). The old home records its move `done` when it first bridges to the new home.
- A message or ring to an agent on an unreachable outpost waits at the home and is delivered when the outpost reconnects. See [inbox.md](inbox.md) for delivery.

## Driving it

The app's Outposts page, the Outpost updates band under the title bar (`outpost-updates`, a region named "Outpost updates") and remote tiles are found by key, and `bridge state '{"of":"outposts"}'` returns the outposts the app holds, so a step can wait on a state before reading the screen.

Preconditions:

- Use the baseline instance with its app, launched as [../SKILL.md](../SKILL.md) says. Then run `bridge wait '{"target":{"key":"home"}}'`. On Linux, run every command that reaches the app inside one `xvfb-run -a -s '-noreset -screen 0 1600x1000x24' bash -c '…'`. The chords below are macOS's. On Linux, Settings is `mod+shift+,`, a split `mod+shift+d` and a new session `mod+shift+n`.
- Make a proof folder with `P=$(mktemp -d /tmp/drive-attn-outposts.XXXX) && echo "export P=$P" >> $DRIVE_ENV`.
- Make an agent folder with `A=$(mktemp -d /tmp/drive-attn-outposts-agent.XXXX) && echo "export A=$A" >> $DRIVE_ENV`, and save this fixture as `$A/.attn-mock-agent.json`:

```json
{"version": 1, "turns": [
  {"includes": "remote shell", "actions": [
    {"type": "attn", "args": ["terminal", "open", "--host", "drive-op"]}]},
  {"includes": "missing host", "actions": [
    {"type": "attn", "args": ["terminal", "open", "--host", "nowhere"]}]},
  {"includes": "remote delegate", "actions": [
    {"type": "attn", "args": ["delegate", "--host", "drive-op", "--agent", "shell", "--model", "none", "--cwd", "/tmp", "--name", "op-delegate", "--brief", "Drive the outpost refusal"]}]}
]}
```

`<terminal>` below is the agent's terminal id from `wsctl list`.

- **Off by default.** Run `wsctl outposts`. It exits 1 with `error: outposts_enabled is off`. `./attn settings get outposts_enabled` prints an empty line.
- **Turn Outposts on in Settings.** `bridge key '{"chord":"mod+,"}'` opens `settings-dialog`, where `settings.nav-off.machines` reads `off`. Press `settings.nav.experimental`, then `settings.feature.outposts_enabled`: `bridge wait '{"target":{"key":"settings.nav-off.machines"},"gone":true}'` answers, `./attn settings get outposts_enabled` prints `true` and `wsctl outposts` prints an empty `outposts_updated`.
- **Enrollment on the home.** Run `./attn enrollment status`. It prints `daemon:` with this daemon's id, `home id:` with the home's `h-` id and `enrollment: home`. `./attn enrollment leave` prints `not enrolled to another home`.
- **Add an outpost in Settings.** Press `settings.nav.machines`. `bridge type '{"target":{"key":"settings.machines.name"},"text":"drive-op"}'`, type `unreachable.invalid` into `settings.machines.destination` and press `Enter`. `bridge state '{"of":"outposts","expect":{"$some":{"name":"drive-op","state":"lost"}}}'` answers with the row and its `id`. `bridge find` of `settings.machine.<id>.state` reads `lost`. Press `settings.machine.<id>` to choose the row, then `settings.machine.<id>.details-toggle`: `settings.machine.<id>.error.text` reads ssh's stderr. An ssh refusal offers `settings.machine.<id>.connect`, Connect in a terminal.
- **Answer ssh in a terminal.**
  - Add a destination whose host key is unknown or whose authentication needs your answer. That outpost's row reads `refused`, shows ssh's stderr verbatim and offers **Connect in a terminal**.
  - Press `settings.machine.<id>.connect`: Settings closes and a focused home terminal opens beside the active tile.
  - Answer ssh's host-key, passphrase, password, 2FA or security-key prompt there. When ssh succeeds, `wsctl outposts` reads `connected` without another action.
  - The terminal stays open with its output. Close it with ⌘W. The terminal appears in no queue, home-screen agent list or live or closed ledger list.
  - If you answer `no` at the host-key prompt, ssh exits 255 and the tile stays with its output and a Resume button. Resume runs ssh again in the same `Connect to <name>` tile, and **Connect in a terminal** then focuses that tile instead of opening another. After a successful connection, Resume refuses with `outpost <name> has no ssh refusal to answer in a terminal`.
  - With a changed host key, the terminal shows ssh's refusal and the row stays refused. Follow ssh's message after checking the machine's identity, then try again.
  - Background master creation pauses while the prompt is open, including across a home daemon restart. Remove and Outposts off cancel an unfinished prompt before stopping the outpost's master.
- **The name home is reserved.** Type `home` into the name and any destination, and press `Enter`: `settings.machines.error` reads `machine name "home" is reserved for the home; choose another name`.
- **An agent reaches for the outpost.** Run `wsctl add-session --cwd $A --agent claude --label op-agent --id op-agent --place`, find its terminal in `wsctl list`, and run `wsctl input --id <terminal> --text "remote shell" --enter`. `./attn agent peek op-agent` shows the refusal `drive-op is unreachable; this needs it now`. `wsctl input --id <terminal> --text "missing host" --enter` shows `no machine "nowhere"; machines: home, …`. `wsctl input --id <terminal> --text "remote delegate" --enter` shows `delegate: drive-op is unreachable; this needs it now`, refused before the delegation is accepted.
- **Re-pair.** Press `settings.machine.<id>.repair`: the state reads `lost` again, after a moment of `connecting`. Nothing was pinned here, since the outpost never answered. `go test ./cmd/attnd -run TestSSH -v` below checks pins.
- **Remove.** Press `settings.machine.<id>.remove`: with no terminals, `bridge wait '{"target":{"key":"settings.machine.<id>"},"gone":true}'` answers and `wsctl outposts` lists none. With terminals, the button reads "Remove and close N terminals", or "Remove and forget N terminals" with `settings.machine.<id>.remove-note` while the outpost is unreachable (for a machine that dials the home, the note says it leaves when it next dials; `TestAMachineRemovedWhileOutOfReachKeepsItsShellUntilItDialsAgainThenLeavesAndStopsIt` proves that), beside `settings.machine.<id>.cancel`; press it again to remove.
- **Turn Outposts off.** `./attn settings set outposts_enabled false`: `settings.nav-off.machines` comes back and `wsctl outposts` refuses again.
- **Install from scratch, update and remove.** Run `node scripts/verify-ssh-outposts/install.mjs --help` for the named Mac and Linux check. It checks fresh Add, Notebook sync, shell survival through Update, remote daemon stop on Remove, retained files and unchanged default-instance files and processes. Keep its receipts, including upload time.
- **A home id outlives its daemon.** Run `./scripts/test-go.sh --packages -run TestAHomeIDOutlivesTheDaemonThatRanTheHome -v ./cmd/attnd`. An outpost enrolled by the build before home ids takes the home id at its first bridge and keeps its shell, its copied settings, its Notebook folders and sync state. Another daemon id presenting the same home id bridges with the shell alive and syncs the Notebook without moving a copy aside. A daemon presenting another home id is refused by name, and a daemon recorded as an outpost never acts as the home.
- **A rollback to the build before home ids.** Run `./scripts/test-go.sh --packages -run TestAHomeAndItsOutpostRollBackToTheBuildBeforeHomeIDsAndUpgradeAgain -v ./cmd/attnd`. A home and its outpost upgraded from the build before home ids, restored with `attn db restore` and started on that build again both start and bridge, because `enrollment.json` keeps `home_daemon_id` for that build. Upgraded again, the outpost re-keys what that build stored under the home's daemon id, so the home keeps its home id, the outpost's shell keeps its pid and screen through every step, and no upgrade moves the Notebook copy aside. The build before home ids resets its Notebook sync state at the rollback, because `attn db restore` does not restore that state.
- **Another home's Add.** Run `./scripts/test-go.sh --packages -run TestOutpostsPairRestartRefuseSecondHomeAndRelease -v ./cmd/attnd`. A first home pairs, keeps its pins through an outpost restart and runs a shell there. A second home on another build adds the same outpost. Before it installs anything, attn refuses the second home, and the refusal names both homes and `attn enrollment leave`. The outpost's binary is unchanged, and the second home's Remove of its refused row leaves the first home's enrollment, bridge, build and shell PID in place. After the first home removes the outpost, the second home's Repair connects.
- **Finish Add after authentication.** Run `go test ./cmd/attnd -run TestSSHUnpairedAddFinishesAfterAuthentication -v`. In the test, ssh first refuses a host key. The test then creates the master out of band, as the terminal does, and checks that installation and pairing finish without Update. Its restart case checks that the saved unpaired row resumes Add. `TestSSHDisablingOutpostsCancelsUnpairedAdd` holds an external request and checks that turning Outposts off cancels Add without a later install.
- **No repeat install after a refusal.** Run `go test ./internal/daemon -run TestAnUnpairedOutpostDoesNotRepeatARefusedInstall -v`. The test fakes the clock and the external SSH refusal. It checks that the home makes one install attempt across repeated retries and continued probes, and one new attempt after Update.
- **One build for outposts updating at once.** Run `go test ./internal/outpostbuild -run TestOutpostsUpdatingAtOnceShareOneBuild -v`. Two outposts on one platform acquire at once, and the release server serves each binary once. For a real build, run `go run ./scripts/outpost-build-probe --callers 2 --home <attnd> --repository <checkout> --cache <empty dir>`. Both callers report building and print the same digests.
- **Pair through ssh.** Run `go test ./cmd/attnd -run TestSSH -v`. The fake ssh models a Linux machine, and the real `_bridge` starts its daemon. The test opens a shell, exits its master, observes lost then connected, reattaches and types again. For a real route, run `scripts/verify-ssh-outposts/transport.mjs` with a fresh named instance. Add installs the matching binary.
- **Typing order and unanswered keys.** Run `./scripts/test-go.sh --packages -run 'TestRemote(Input|Reload|TerminalRefusals|TileActions|Wait)' -v ./cmd/attnd`. It drives real paired daemons through the app protocol: later keys echo while an earlier answer is held, resizes precede later keys, reloads wait, and remote actions leave local typing responsive. Keys still unanswered at bridge loss produce probe and support-trace errors without a refusal flash. A refusal of keys sent while offline or connecting names the terminal, and those keys never reach the terminal. Use `scripts/verify-ssh-outposts/transport.mjs --mode idle` to measure typing echo on a real route.
- **Shells, agents, offline tiles and updates.**
  - Add the Linux box's ssh destination in Settings. Add installs the home's build for the same instance name.
  - Run `wsctl add-session --host <name> --agent shell --cwd <dir>`: it opens a shell there and its tile header's `tile.<leaf>.host` is named for the outpost.
  - With that shell's tile active, press `mod+d` (`terminal.splitVertical`): a second shell opens beside it with the same host.
  - Make only the test outpost's connection silent: after 3 seconds, `tile.<runtime id>.reach` reads `<name> not responding`. After 60 seconds, it reads `<name> unreachable · typing is not sent`, the row's state reads `lost`, and `tile.<leaf>.state` reads `offline`.
  - Restore the connection: the strip goes and the tile shows the current screen.
  - Re-pair while that outpost cannot answer: its tiles read `Connecting to <name> · typing is not sent`. Restore it and check that this notice clears too.
  - With a different build, the `outpost-updates` band and the chosen row's "Update" install the home's build and reconnect. The shell keeps its PID.
  - The baseline cannot do this, as Gotchas says. The scenarios drive these through a fake ssh and a second daemon: `native-outposts-settings` (Connect in a terminal, a remote shell, its split and a remote agent, stalled, unreachable and connecting tiles, refused typing never replayed, the offline queue, Home and palette, Re-pair and Remove), `native-outpost-update` (the band and the row's update) and `native-notebook-sync`. On a tile, `tile.<runtime id>.status` is the strip, and `tile.<runtime id>.screen-on` reads `The screen is on <name>.` on a tile that never showed the screen.
- **Launcher reads on an outpost.** Run `./scripts/test-go.sh --packages -run TestLauncherReadsRunOnTheNamedOutpost -v ./cmd/attnd`. Through the app protocol, each read with `host` answers from the outpost's registry and harnesses, and with the outpost lost each fails at once with `<name> is unreachable; this needs it now`. On a Linux box, `wsctl request --event browse_directory_result --json '{"cmd":"browse_directory","host":"<name>","input_path":"~/","request_id":"b1"}'` lists that machine's home with its `home_path`, and `--json '{"cmd":"agent_catalog","host":"<name>","request_id":"c1"}' --event agent_catalog_result` lists the harnesses installed there.
- **Machine paths in the launcher.** With an outpost added and Launcher 2.0 on, press `mod+n` and type `ai` with `bridge type`: the first row is a machine row under "Browse a machine", reading `ai-sandbox:`. Press Tab: the field reads `ai-sandbox:~/` and the rows are that machine's folders. A recent's machine badge is `new-session.row.<i>.machine`. Type a folder that only another machine has: `new-session.status` reads `<dir> is not on <name>` and a row under "Found elsewhere" names the machine that has it. The baseline cannot do this: it needs a reachable outpost.
- **Agent tools on an outpost.** On the same Linux box, with Claude Code installed and signed in there:
  - Run `./attn settings set agent_tools_enabled true` at the home and plant a seed.
  - Run `wsctl add-session --host <name> --agent claude --cwd <dir> --id op-claude --place --initial-prompt-file <file>` with a prompt asking it to note on that seed with the attn MCP tool `attn_do` and do nothing else. Answer Claude's folder trust question with `wsctl input --id op-claude --text $'\e[B'`, then `$'\r'`.
  - `./attn seed notes <seed>` at the home shows the note by `op-claude`. On the outpost, `grep 'agent tools' <outpost data dir>/daemon.log` shows `seed_note by terminal <id> (session op-claude): ok`.
  - The baseline cannot do this either.
- **Resume an outpost session from the ledger.** On the same Linux box, with Claude Code installed and signed in there:

## Contexts

- **Durability across restarts**: the outpost list, its pins and an outpost's enrollment are kept by each daemon, and the home redials after any restart. A shell on an outpost keeps running through a lost bridge and a restart of either daemon, and the shell's screen comes back on reconnect. If the shell's process is gone, the home marks the shell recoverable, and Resume starts a new shell in its place. A home restart resumes an accepted delegation onto an outpost on the same machine and path.
- **Linux**: the outpost daemon runs on Linux detached from ssh, built with `make build-linux-amd64` or `make build-linux-arm64`. `scripts/verify-ssh-outposts/transport.mjs` checks that its daemon and shell keep their PIDs after a master exit. The app stays on the Mac.
- **Profiles**: outposts belong to the home and serve every profile. A terminal on an outpost belongs to the profile that started it, and Remove closes the outpost's terminals in every profile.
- **Performance and idle cost**: each connected bridge exchanges a heartbeat every 0.5 seconds. `scripts/verify-ssh-outposts/transport.mjs --mode idle` measures typing latency against an echo through the same master. Nothing measures their idle CPU or counts heartbeat-related facts.
- **Harnesses**: a new session runs on an outpost when the outpost's `agent_catalog` offers the harness, with that machine's own executable and credentials; otherwise the home refuses with `agent "<id>" is not available on <machine>`. An open session revives on its outpost after the catalog stops offering its harness, as at the home, such as a Sigma session after `sigma_enabled` turns off; a harness the catalog lists as missing is refused either way. A plugin harness also needs its plugin at the home, which builds the launch. A Sigma session on an outpost uses the outpost's own Sigma server: the outpost starts it, recovers it after a restart, takes the close interrupt, and answers `agent_catalog` with `models_for: "sigma"`. The home starts no Sigma server for it. The chief and the crew run only at the home, and attn refuses a request to start them on an outpost and names that limit.
- **Keyboard and native input**: ⌘D in an outpost shell opens another shell on that outpost. Keys, resizes and pointer activity stream in order while connected or stalled. The tile flashes red when a key is refused before it reaches the bridge or refused by the outpost. The tile counts those keys as possibly unsent. An unanswered key at bridge loss does not flash and may still run. attn retries no key.
- **Compatibility across versions**: the home and the outpost must run the same build and the same instance name. Add continues until first pairing, including after ssh authentication or a home restart. After a failed install, attn starts no new install until the user chooses Update or Re-pair. A reconnect retries only the probe. Re-pair clears the pin and repeats Add. The home refuses a pinned reconnect to a different build or to an outpost with nothing installed. Choose Update in the row or banner to install the home's build.
- **Flow**: an offline agent keeps its queue row, marked, but Next, automatic advance, ⌘J and the waiting counts skip it, and settle, snooze, unsnooze and countdown cancel are hidden.

## Gotchas

- The baseline has nothing to connect to: an added outpost ends `lost`, or `refused` when ssh refuses authentication or a host key. `go test ./cmd/attnd -run TestSSH -v` proves the bridge states only. Shells, agents, offline tiles, ledger resume, notebook sync and updates need a Linux box with the setup in `docs/guide/reference/using-outposts.md`. That outpost runs its machine's own Claude Code and Codex, never the mock agent.
- A named instance pairs only with an outpost of the same instance name, never with production or another name. `go test ./cmd/attnd -run TestSSH -v` sidesteps this with two daemons in temporary data folders.
- On an outpost newly added or joined, the home refuses a spawn there until the outpost's first sync of the Notebook folder completes, with `<name>'s first sync of the Notebook folder <root> has not completed: …`. Wait until `wsctl outposts` shows that outpost's `"notebook"` with `"state":"in_sync"` before you spawn on it.
- Every outpost command refuses while Outposts is off: `outposts_enabled is off; run attn settings set outposts_enabled true before you add an outpost`.
- The bridge uses the user's OpenSSH configuration. Every background command uses BatchMode and shows ssh's stderr on failure. The master survives a lost bridge and a home restart. Remove, Outposts off and instance clean exit the master.
- `attn enrollment` reads the data folder of the attn it runs as. Run it on the outpost to see the outpost's side. On the home it always says `home`.
- Stalled and connecting notices appear only on tiles. Sidebar, queue and home screen offline marking still follows reachability. Connecting refuses typing, while stalled keeps sending typing.
- Working but wrong: the ledger's "Reopen" and `attn session reopen` say Reopen where the glossary says resume. Files on an outpost do not open on the Mac yet: Open in editor and ⌘-clicked paths in an outpost shell fail and name the outpost.
