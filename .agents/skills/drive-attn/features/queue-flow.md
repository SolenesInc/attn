# Queue flow

Queue flow brings the user the next agent that needs them and moves them on
after every prompt. An agent that stops is owed a turn. The queue lists turns
with priority first, then oldest first. The user settles a turn when they are
done with it, snoozes an agent until later, or marks an agent as priority.
Auto-settle can close a turn once the user has steered the agent and the agent
went back to work. Agents put themselves in the queue with
`attn turn open` when they cannot go on without the user, or when they finished
work the user should read. Automation runs never
queue, but the user settles a run's turn the same way in either flow.

## Sub-features

- `flow-switch`: turn queue flow on or off. The sidebar changes shape with the flow ([sidebar.md](sidebar.md)).
- `turn-open`: a turn opens when an agent stops, or when it asks with `attn turn open`.
- `queue-order`: priority turns first, then the oldest. Shells and automation runs never queue. Crew members, the Chief included, queue when `queue_crew_enabled` is on.
- `jump-to-waiting`: open the turn at the head of the queue. An off-screen document an agent opened comes first ([desktops.md](desktops.md)).
- `close-jump`: closing the agent on screen does what `jump-to-waiting` does. The Triggers section says when it stays put.
- `walk`: step through the queue's agents in order: the turns, then the working agents, then the snoozed ones.
- `settle`: close a turn. The user moves on to the next turn, or home when none is left.
- `run-settle`: close an automation run's turn, in either flow. The user stays on the run (see [automations.md](automations.md) for runs).
- `settle-move-on`: in queue flow, ⌘⇧E on an agent that is owed no turn moves the user on. The Keys bullet under "How to get to it" says where.
- `auto-settle`: close a turn once the user steered the agent and the agent kept working, after a visible countdown.
- `countdown-cancel`: stop the countdown and keep the turn. A second press lets the turn settle again.
- `snooze`: put an agent off until a set time. The user moves on.
- `unsnooze`: end a snooze early. The agent's turn comes back at the back of the queue.
- `priority`: mark an agent so its turns go first.
- `quiet-notifications`: on by default. attn opens no turn at the stop of a notification run unless the agent opened one with `attn turn open`. A quick capture makes the run the user's, so its stop opens a turn, and the turn that reply leaves owed stays owed, at its place, through every notification run after it until the user settles it. Those runs do not settle it, do not print the quiet note and do not start auto-settle.
- `supervisor-opens`: with `attention_supervisor` on, attn opens the turn of an agent that stopped quietly once the attention supervisor's verdict on it is open, and the turn carries the verdict as `Session.attention` until it settles. The supervisor never opens a turn while one is owed, and never settles one.
- `supervisor-notices`: with `attention_supervisor` on, the supervisor asks before it opens a turn that someone other than the user can settle. An agent waiting on a background task gets an inbox notice at 60 min and 4 h into the wait, and at 20 min when the verdict calls it stuck; its turn opens when it makes no model request within 5 minutes of a notice, or keeps waiting after the 4 h one. A delegate whose result goes to a live dispatcher has that dispatcher asked first, and its turn opens only when the dispatcher makes no model request within 5 minutes. With the setting off, the daemon log has each notice it would send.
- `turn-guidance`: what attn tells its agents about turns.

## How to get to it

### People

- Keys (`native/crates/attn-app/src/keymap.rs`): ⌘J (`session.jumpToWaiting`) opens the head of the queue, or first an off-screen document an agent opened ([desktops.md](desktops.md)). ⌘↑ (`session.prev`) and ⌘↓ (`session.next`) step to the previous or next agent of the queue, wrapping, and from home start at the queue's first or last row ([desktops.md](desktops.md) has them in desktop flow). ⌘⇧E (`session.settle`) settles. ⌘⇧S (`session.snooze`) opens the snooze menu. ⌘⇧I (`session.priority`) toggles priority. ⌘. (`session.cancelCountdown`) stops a countdown, or keeps the next turn of the agent on screen. Settle, snooze and priority act on the focused queue row, otherwise on the agent on screen. ⌘⇧E settles an automation run's turn in either flow, and in desktop flow nothing else. In queue flow, ⌘⇧E on an agent of the queue that is owed no turn and is not snoozed settles nothing. ⌘⇧E then moves the user to the head of the queue. When no turn is owed anywhere, ⌘⇧E moves the user home with "Take me to the next agent that needs you" checked.

- Their own shell: `attn settings set queue_mode_enabled true`, and the `attn session` verbs below, which work from a plain shell.

### Agents

- `attn turn open|settle`, and the tools `turn_open` and `turn_settle` over `/mcp` when `agent_tools_enabled` is on (`internal/catalog/content/turn.yaml`, `internal/daemon/commands_turn.go`): `open` puts the calling session in the queue. `settle` takes the session out of a turn that the session opened itself. If the session is working when it runs `open`, the turn opens when the session stops. Both work in either flow; with queue flow off there is no queue to show, and the turn still notifies the phone.
- `attn session snooze <id>... --until <when>` and `attn session unsnooze <id>...` (`cli/attn/src/commands/session/`, `internal/daemon/commands_session.go`; the tools `session_snooze` and `session_unsnooze`): a session may snooze itself and the agents below it in its delegation chain. The chief may snooze any agent of the chief's profile. `--until` takes an RFC3339 instant, a positive duration such as `30m` or `1h`, or `tomorrow`, `saturday` or `monday` at 09:00 in the home's local time.
- `attn session priority on|off [--session <id>]` (the tool `session_priority`): any agent may mark any session.
- Reads: `attn state explain <id>` prints `latest verdict:` with the attention supervisor's verdict, label, decider, time and reason, whether or not attn acted on it (`internal/daemon/monitor_trace.go`). `attn agent list` shows `owed` in its TURN column (`cli/attn/src/commands/agent/`). `attn session list --tree` shows `owed` or `snoozed until <instant>` (`internal/daemon/commands_session_tree.go`).
- The queue's settings through `attn settings` ([settings.md](settings.md), `internal/daemon/settings_registry.go`): `queue_mode_enabled`, `queue_crew_enabled`, `queue_show_hidden_sessions`, `queue_quiet_notifications`, `auto_settle_enabled`, `auto_settle_arm_seconds`, `auto_settle_countdown_seconds`, and the experimental `attention_supervisor`.
- `attn callout` can point at the `queue` anchor, the waiting card or, on the queue bar, the waiting pill ([callouts.md](callouts.md)).
- Prompts: `attn turn --help` and the tools' descriptions, both generated from `internal/catalog/content/turn.yaml`. The supervisor's notices, `attention/wait-check` and `attention/delegate-check` (`internal/prompts/content/attention/`), which `attn agent inbox` prints. The note that `attn agent inbox` prints after the items (`internal/prompts/content/session/inbox-quiet.md`) when a notification started the run and quiet notifications keep the run's stop out of the queue. The orchestration reference that tells agents to open their turn before ending with questions (`internal/prompts/content/skills/attn-workflow/references/orchestration.md`).

### Triggers

- A turn opens when an agent's state becomes one of waiting, idle, needs approval or unknown. Shells are never owed one (`internal/attention/turn.go`). With quiet notifications on, a stop after a notification run opens a turn only for approval, an unknown state, a run that ended on an error, or an agent that ran `attn turn open`.
- With `attention_supervisor` on, an open verdict opens the turn of a stopped agent that is owed none and is not snoozed. The supervisor judges a quiet stop 15 minutes after it, a stopped agent when a seed, standby or delegate its last verdict read changes, a background wait, or a working agent whose harness reports each finished step (`Signals.ReportsSteps`, Claude Code today), 20 min, 60 min and 4 h after its last model request or finished step, and at daemon start each stopped agent whose stop it has not judged (`internal/daemon/attention_checkpoints.go`, `internal/daemon/attention_actions.go`). A background wait's checkpoints count from where the wait began, not from the agent's answers to notices, and no elapsed checkpoint falls in the 5 minutes after a daemon start. The home sends the outpost's monitor `monitor_command` `surface`, which refuses while a turn is owed, while the agent is snoozed or once it is no longer stopped. At a background wait's elapsed checkpoint a notice replaces that, except for an open verdict labelled "asks you", which opens the turn; `supervisor-notices` says who gets a notice and when. `attn debug attention` lists each `notice to`, `supervised wait ended` and dispatcher's `answer window … ran out`, and `attn debug daemon-log --grep attention` shows each verdict and each refused surface.
- A snooze ends at its deadline and the turn opens again if the agent is stopped. An agent that exits or turns unknown ends its own snooze (`internal/sessionmonitor/turns.go`).
- attn arms auto-settle after the arm delay once the user's prompt set the agent working, counts down, and settles the turn. Typing or moving the pointer holds the countdown until five quiet seconds pass (`internal/sessionmonitor/autosettle.go`).
- When the turn of the agent on screen closes and no navigation of the user's own is under way, the app moves them to the head of the queue if it is a priority turn, otherwise to the next owed turn, or home with "Take me to the next agent that needs you" checked when none is owed. The app does not move them when the agent closed the turn itself (`turn_by_agent`) or the agent is offline (`advance_after_turn_closed` in `native/crates/attn-app/src/sidebar/queue.rs`).
- When the user closes the agent on screen in queue flow, the app jumps as ⌘J does, past the closing agent: with ⌘W, the pane's ⌘W in a split, or the row's "Close session". With nobody waiting, the user stays where the close leaves them. The app does not move them for a shell, one of two tiles showing the agent, an agent that is not on screen, a close refused for crew, the Chief or an offline host, or an agent closed from the CLI (`move_on_from` in `native/crates/attn-app/src/sidebar/actions.rs`).

## Driving it

Preconditions:

- Use the baseline instance with its app, launched as [../SKILL.md](../SKILL.md) says, then `bridge wait '{"target":{"key":"sidebar"}}'`. On Linux, run every command that reaches the app inside one `xvfb-run -a -s '-noreset -screen 0 1600x1000x24' bash -c '…'`. The chords below are the macOS ones. On Linux, the keys are those under Contexts, and the palette is `mod+alt+k`. The baseline starts in desktop flow with auto-settle off.
- Make a proof folder with `P=$(mktemp -d /tmp/drive-attn-queue.XXXX) && echo "export P=$P" >> $DRIVE_ENV`.
- Make two agent folders with `A=$(mktemp -d /tmp/drive-attn-queue-a.XXXX) && echo "export A=$A" >> $DRIVE_ENV` and `B=$(mktemp -d /tmp/drive-attn-queue-b.XXXX) && echo "export B=$B" >> $DRIVE_ENV`. Save this fixture as `$A/.attn-mock-agent.json`:

```json
{"version": 1, "turns": [
  {"includes": "question", "actions": [{"type": "reply", "text": "Which option do you want?"}]},
  {"includes": "longrun", "actions": [{"type": "delay", "ms": 40000}, {"type": "reply", "text": "long run done"}]},
  {"includes": "settleturn", "actions": [{"type": "attn", "args": ["turn", "settle"]}, {"type": "delay", "ms": 15000}]},
  {"includes": "selfsnooze", "actions": [{"type": "attn", "args": ["session", "snooze", "queue-a", "--until", "1h"]}]},
  {"includes": "selfwake", "actions": [{"type": "attn", "args": ["session", "unsnooze", "queue-a"]}]},
  {"includes": "markpeer", "actions": [{"type": "attn", "args": ["session", "priority", "on", "--session", "queue-b"]}]},
  {"includes": "unread items", "actions": [
    {"type": "attn", "args": ["agent", "inbox"]},
    {"type": "attn", "args": ["turn", "open"]}]}
]}
```

- Save this fixture as `$B/.attn-mock-agent.json`:

```json
{"version": 1, "turns": [
  {"includes": "question", "actions": [{"type": "reply", "text": "Which option do you want?"}]},
```

- Start the agents in order. Run `wsctl add-session --cwd $A --agent claude --label queue-a --id queue-a`, re-read `./attn agent list` until `queue-a` shows `owed`, then do the same with `$B`, `queue-b` and `queue-b`. The wait makes `queue-a` the older turn. `<terminal-a>` and `<terminal-b>` are their terminal ids from `wsctl list`.
- Get an automation run that is owed a turn. Make a run folder with `R=$(mktemp -d /tmp/drive-attn-queue-run.XXXX) && echo "export R=$R" >> $DRIVE_ENV`, save `{"version": 1, "turns": [{"includes": "question", "actions": [{"type": "reply", "text": "Which option do you want?"}]}]}` as `$R/.attn-mock-agent.json`, and write and apply a manual automation that starts its runs there, with the paths filled in:

```bash

api_version: attn.dev/automations/v1alpha1
name: Queue run
trigger:
  type: manual
prompt: |
  Ask the user a question.
launch:
  driver: codex
  model: mock-agent-1
  executable: $ATTN_CODEX_EXECUTABLE
location:
  type: directory
  path: $R
EOF
./attn automation apply --file $P/run.yaml --launch-desktop own --desktop-name "Queue runs"
```

  `<automation-id>` is the `id` that `./attn automation apply` prints. Run `./attn automation run <automation-id>`, then re-read `./attn automation runs <automation-id>` until the run is `delivered` with a `session_id`. That id is `<run>`. Then re-read `./attn agent peek <run>` until it shows `turn: owed to this session`. `<terminal-run>` is the run's terminal id from `wsctl list`.

`bridge state '{"of":"window"}'` names the agent on screen in `on_screen`, and `null` at home. `<pane-b>` is the `pane_id` of `queue-b`'s pane in `bridge state '{"of":"desktops","includes":"queue-b"}'`. To open the palette, press `mod+shift+k`, type the command's title and press `Enter` once `palette.row.command:<id>` shows. A row's controls show while the pointer is on the row, and `bridge press` moves the pointer there first.

## Contexts

- **Durability across restarts**: a turn the supervisor opened keeps its verdict across a restart, and a restart judges no stop the supervisor already judged, so it does not reopen a turn the user settled (the decision log, `attention-decisions.jsonl` in the data dir). A waiting agent keeps its background tasks and run starter, a supervised wait keeps its notices and its 5-minute answer deadline, and a dispatcher asked about a delegate keeps its 5-minute deadline: the delegate's turn opens at the original deadline, or at start when the deadline passed while the daemon was down, unless the dispatcher made a model request after the notice. Turns, settles, snoozes and priority are the daemon's records. A settle and a snooze survive a daemon restart, a snooze still ends at its deadline afterwards, and an agent's request for its turn outlives a restart.
- **Linux**: `session.jumpToWaiting` is Ctrl+Shift+J, `session.prev` and `session.next` Ctrl+Shift+PageUp and Ctrl+Shift+PageDown, `session.settle` Ctrl+Alt+E, `session.snooze` Ctrl+Alt+S, `session.priority` Ctrl+Alt+I and `session.cancelCountdown` Ctrl+Shift+. there (the `LINUX` table in `native/crates/attn-app/src/keymap.rs`). There is no menu in the way of the cancel key. `attn turn` and `attn session` work the same.
- **Outposts**: an agent whose outpost is offline is left out of the waiting count, has no settle or snooze in the app, and is skipped when the queue moves the user on. Its countdown shows "Settling paused while the host is unreachable".
- **Profiles**: each profile's queue lists only its own agents, and only that profile's chief may snooze any of them. Queue flow itself is one setting for all profiles.
- **Performance and idle cost**: the app re-reads the clock for turn ages every 30 seconds, and the countdown bar animates only while a countdown runs. Nothing measures the queue's idle cost. When a change touches the queue's rendering, check for repaints with `docs/internal/perf-testing.md`.
- **Harnesses**: a turn opens on the state attn reads from each harness ([agent-state.md](agent-state.md)). `attn turn` and `attn session` work the same from Claude Code, Codex and plugin harnesses. Shells never queue.
- **Keyboard and native input**: ⌘J, ⌘↑, ⌘↓, ⌘⇧E, ⌘⇧S, ⌘⇧I and ⌘. reach every action. In a text field outside a terminal, ⌘↑ and ⌘↓ stay with the field. The snooze menu takes arrows and Enter, and Escape returns focus to where it was. While the snooze menu is open, app shortcuts and the palette do not run. ⌘. arrives through the File menu's Stop Countdown item, which carries the keys `session.cancelCountdown` is bound to. With the agent list open, ↓ and ↑ walk its rows, and ⌘⇧E, ⌘⇧S and ⌘⇧I act on the selected row.
- **Compatibility across versions**: a snooze written in the old encoding still ends, and store migrations carry turn stamps and snooze deadlines forward. The flow is stored under its old key, `queue_mode_enabled`.
- **Flow**: with queue flow off, turns are still tracked and `./attn agent list` still shows `owed`. The sidebar shows desktops, and ⌘↑ and ⌘↓ step through desktops instead ([desktops.md](desktops.md)). ⌘⇧S and the palette's snooze commands are gone. ⌘⇧E, "Settle this agent" and the sidebar's ✓ settle only automation runs, and ⌘⇧E on any other agent does nothing. ⌘J opens the agent that has waited longest among those waiting, needing approval or unknown. An idle agent is never the target of ⌘J. An agent's `attn turn open` still opens its turn, which pushes to a paired phone.

## Gotchas

- A mock agent is owed a turn as soon as it finishes booting, in either flow. Expect `owed` before any prompt.
- Typing into an agent does not settle its turn. Only a settle, a snooze or auto-settle does. A turn the agent did not open is the user's: `attn turn settle` from the agent exits 1 with `only the user settles it`. The agent can settle a turn that the agent opened with `attn turn open`.
- Every prompt ends in a stop, and attn opens a turn at each stop. After each `wsctl input` the agent is owed a turn again, unless the agent is snoozed or a notification run started it with quiet notifications on. Settle between steps that expect `-`.
- `attn turn` acts as the calling session. From a plain shell, `attn turn` prints the queue-off line while queue flow is off and is refused once queue flow is on. Drive it through the mock agent.
- From a plain shell, `attn session snooze` and `unsnooze` may act on any live session. From an agent, they follow the delegation-chain rule. A shell's success is not proof of what an agent may do.
- Auto-settle arms only after the user's input. `wsctl input` counts. A ring or `attn agent msg` does not. The scenarios type the prompt and Enter as two inputs, and so does this recipe.
- The arm delay is at least 5 seconds and the countdown is at least 3 seconds. `attn settings set` refuses less. The agent must keep working past both: a stop ends the countdown, and attn opens the turn again.
- Typing or moving the pointer pauses the countdown (`SETTLING PAUSED`) until five quiet seconds pass. `wsctl input` into the agent's terminal counts as typing.
- Pressing ⌘. again after a cancel does not resume the old countdown. The press lets the next countdown start, so `SETTLING…` returns only after the arm delay.
- On macOS ⌘. comes through the File menu, which `bridge key` does not reach. Press the real ⌘. too, as the step says. If ⌘. has no effect, keep the failed receipt and diagnose. With no countdown on screen, ⌘. keeps the next turn of the agent on screen, so a stray press shows `TURN KEPT` later.
- A row's ✓, ☾, ↩ and ••• buttons show only while the pointer is on the row. `bridge press` moves the pointer there first.
- The mock agent prints errors and replies at the terminal's width, so a long line wraps anywhere. Match the first words of a line, not its ending.
- ⌘⇧S and the palette's snooze and unsnooze commands exist only in queue flow and only with an agent on screen. "Settle this agent" shows in either flow, but only while the agent on screen is owed a turn the user can settle: in queue flow an agent of the queue or a run, in desktop flow only a run. A missing palette command usually means the precondition is missing, not that the command is broken.
- A ⌘⇧E that jumps instead of settling means the turn had already closed.
- Finished off-screen runs fold under `sidebar.automations.finished` in the queue sidebar; a run that owes a turn, is working, or is on screen stays visible directly under `queue.runs`.
- attn rings an agent 30 seconds after the last `wsctl input` into that terminal. Quiet notifications change nothing while queue flow is off.
- Turn ages tick every 30 seconds. A fresh turn reads `now`.
- `queue_show_hidden_sessions` matters only for sessions without a tile, which come from shared Codex ([shared-codex.md](shared-codex.md)). The baseline has none.
- Working but wrong: the palette calls queue flow "the agent queue", and the shortcut sheet labels ⌘↑ and ⌘↓ with the old name for queue flow. The row menu says "Unmark priority" where the palette says "Clear priority". The flow is one setting shared by every profile.
