# Asks

An agent asks the user a question and keeps working. The user answers in
their own time, and the answer reaches the agent's conversation. An ask is
markdown with question blocks: pick one, pick any, write an answer, or attach a file. People
answer every agent's asks from one sheet that holds the window under the title bar, one after another, without opening
the agents' terminals. attn types the answer into the asking agent's
conversation as the user's message. An ask about a seed goes to whoever tends
the seed by the time the user answers, and attn saves the answer as a note on
the seed. The seed stays open until the user answers: an agent's harvest
refuses and names the open asks, while the user's own harvest and any wither
withdraw them. Asks are on by default, and an agent keeps the setting it launched with.

## Sub-features

- `ask-open`: an agent opens an ask from markdown on stdin or a file and gets its id at once.
- `ask-images`: the local images an ask shows, copied to the home when the ask opens and shown in the sheet from that copy.
- `ask-references`: the files an ask's links, in its markdown and in a `--subject` the agent wrote, name and the folders named after a code block's language (` ```sh far:/srv/x `), resolved by the home when the ask opens or is amended into `Ask.references`, each with its machine. `<machine>:<path>` names the machine; a link without one is on the asking session's machine, relative to the ask's `base_dir`, as images are. A `~` path on another machine is read there through `terminal_shell`. A destination written `<scheme>://`, and `http:`, `https:`, `mailto:`, `attn:` and `file:` ones, is a URL and never a machine path. A machine no machine or several hold is refused with the line, or "the subject", and the machines, and an amendment's relative link that names another file from the folder it was written in is refused. The sheet opens a file link from its machine: markdown in the panel (`ask-panel`), on any machine, the app's included, and another kind with the system's opener on the app's machine; the phone shows `<machine> · <path>` beside the link's words instead of a link (`[data-testid="ask-file"]`). Asks opened before references keep their links resolved by the app as before.
- `ask-questions`: `:::question`, `:::question-multi` and `:::question-text` blocks, with choices, reasons and a recommended choice. A kind the app does not know shows its prompt with `asks.q.<key>.unknown` ("Update attn to answer it") and takes no keys.
- `ask-file-questions`: a `:::question-file` block asks for a screenshot or a file; it takes no choices, `Recommended:` or `Default:`. The answer text puts each file's line under that question, or `Unanswered.` when the user attached none. The phone shows it as "Answer this in the native app."
- `ask-default`: `Default: <choice> after <duration>` in one `:::question` of an ask. When no answer has come by then, the ask's addressee gets one notice naming the choice; the ask stays open and a later answer arrives as usual. Until the ask is answered, the sheet shows `asks.default`, "No answer by <time>, and <agent> goes with <choice>", on the user's clock, and its row in the list reads "default <time>". The phone shows the same line, and `c` copies the `Default:` line with the ask.
- `ask-sheet`: the sheet where people read and answer asks one after another, under the title bar, its list beside the ask, or above it in a narrow window.
- `ask-panel`: the panel right of the question (`asks.panel`), one per ask, with a tab for each seed, markdown file and, on macOS, web page opened from the ask (`asks.panel.tab.<n>`, named by the seed's title, by the file's name and `· <machine>` when it is on another machine, or by the page's host). A seed shows the garden's seed page (`asks.panel.seed.*`, read with `seed_document_get`), with "Reveal in Garden" (`asks.panel.seed.open-garden`), which closes Asks and opens the seed in the Garden. A markdown file is read from its reference's machine with `tile_document_read` each time its tab opens or is shown again, with no live watch, and drawn in `asks.panel.document`; a link in it to another markdown file or a seed opens another tab. ⌘⇧] and ⌘⇧[ move between tabs and wrap round, ⌘W or "Close this tab" (`asks.panel.close-tab`) closes the shown one, and the last close takes the panel away. With the panel open, the question keeps its 652-point column left of the panel beside the rail when the window is 1360 points wide or more; a narrower window lists the asks over the question, and the question gives up width so the panel keeps 420, down to half the window each. A web page shows in the panel's own `WKWebView` over `asks.panel.page`, never in the desktop's browser tile, which keeps its page; the panel's page lives while Asks is open and the ask on screen has a web tab, goes to a web tab's address when that tab is shown after another web tab, hides while a callout or a popover covers Asks, and is not in the accessibility tree or `bridge shot` (take `scripts/vm shot`). A click in it gives it the keyboard until the sheet's focus moves or the sheet is pressed; ⌘R, ⌘[, ⌘] and the zoom keys act on it then. On Linux a web page opens in the system browser. Tabs are the app's state: they are forgotten when the ask leaves the list or the app restarts. An agent's id still opens its card.
- `ask-commands`: each top-level `sh`, `bash`, `zsh`, `fish` or `shell` block of an ask's markdown (`asks.command.<n>`, numbered through the ask) with **Open in terminal** (`asks.command.<n>.open`, keycap `t` on the first, shown until the ask is answered) and `<machine> · <folder>` (`asks.command.<n>.place`): the block's `command` reference, or the ask's `host` and `cwd` (else `base_dir`) for a block that names no place. It sends `spawn_session` with agent `shell`, that host and folder, `typed` set to the block's text and `placement.ask_id`, and opens the shell as a panel tab (`asks.panel.tab.<n>`, named `<folder> · <machine>`) that holds the keyboard (`asks.panel.terminal`, focused) and shows "Starting a shell…" until the home binds it. Every key, Escape, Tab and a paste included, types into the shell; the Asks chord, ⌘↩ and the tab chords stay the sheet's, and the Asks chord gives the keyboard back to the question. A command already open shows its tab again. The tabs come back after an app restart from the home's `terminal_bindings` with `ask_id`, and the cold row before the home answers leaves those shells out. `asks.send` reads "Send and stop" ("Send to Chief and stop") while a command runs in one of the ask's shells (by OSC 133). Closing the tab ends the shell (`unregister`). "Move to desktop" (`asks.panel.move`) sends `desktop_show_session`: the home places the shell beside the asking agent's newest tile, else on the current desktop, the binding loses its `ask_id`, the tab goes, and the shell outlives the answer. The phone shows each shell block with Copy (`[data-testid="ask-command"]`) and `<machine> · <folder>` (`[data-testid="ask-command-place"]`), from `commands` and `runs_at` on the gateway's ask; a block inside a list gets no button on the desktop.
- `ask-answer`: the user's answer, typed into the addressee's conversation as the user's message, or the Chief's with `to_chief` (`ask-stranded`).
- `ask-condition`: a condition the user puts on a choice question's pick ("yes, but skip the Windows VM step"). The answer text gives it as `Their condition: …` after the answer line; a condition without a pick is refused. The native sheet and the phone show a replied answer's condition.
- `ask-answer-files`: files an answer carries on its note, uploaded owned by the ask and committed with the answer. The answer text carries Quick Capture's file lines, so the agent fetches each with `attn agent attachment <id> --out <path>`, and the seed note keeps the same lines. The phone names a replied answer's files.
- `ask-drafts`: what the user has written for an open ask and not sent: picks, Other, written answers, conditions, the note, and the files on the note and on each file question. The native app saves it whole to the daemon (`ask_draft_save`) 0.4 s after writing pauses, and again once the daemon is back after a save it never answered, and again at the next edit after one it refused (the sheet says `Your draft was not saved: <the daemon's error>` until a save is taken, and says nothing for an ask answered or closed meanwhile), with a generation the daemon refuses at or below its own, and seeds the sheet from `Ask.draft` at start, for each ask it holds no draft for. A file that was still uploading when the app quit comes back failed, to remove and attach again. The draft goes when the ask is answered or closed. Agents never see it: `attn ask show` and `ask list` carry no draft. The phone keeps its own draft in memory.
- `ask-replied`: asks answered in the last day, shown again with their answers.
- `ask-follow-up`: the user's follow-up on a replied ask, from its Follow up in the sheet, typed into the conversation of whoever holds the ask now, or the Chief's with `to_chief`, as the answer was, and kept as a note on its seed. When no session holds the ask, the follow-up waits for the next holder, and the notice names who it waits for: the seed's next tender, a tender on standby, or the crew member's next session. A tender on standby that seed mail resumes is resumed, and the notice says so. An open ask refuses it in favour of an answer, and a forgotten one refuses it. The phone has no follow-up.
- `ask-on-seed`: an ask about a seed the agent tends, answered to the seed's tender and kept as a note. An ask without `--seed` is about the delegation stake only while the agent still tends it; after a park it is about no seed.
- `ask-holds-harvest`: an agent's harvest of a seed with an open ask refuses and names each ask. The tender's park and replant refuse the same way, and so does arming `--when-merged` by anyone but the user. A harvest-on-merge for an ask opened after arming clears its arming instead. A wither or the user's harvest withdraws the asks, `seed wither` names them, and attn tells each asking session that is still open.
- `ask-keeps-session-open`: an agent that asks ends its turn and its session stays open. `attn seed standby` without `--stay` refuses while the session holds an open ask, about that seed, another seed or none, names each ask and the two commands for a user who asked the agent to close: `attn seed standby <seed> --stay`, then `attn agent close --self`. `attn agent close --self` refuses while the close would strand an ask it holds (`ask-stranded`). A compacting close, from `--compact` or from a standby, checks again once its compact has an outcome: an ask opened in a turn in between keeps the session open, and a notice in its inbox names each ask (`TestACompactingCloseKeepsTheSessionOpenForAnAskOpenedInALaterTurnAndSaysWhy`).
- `ask-stranded`: an ask no agent would take an answer for carries `stranded` on the wire and on the phone: the asking session closed, or nobody tends its seed and no standby resumes a tender for an answer (`garden.tender_resume` other than `any`, or a blocked resume). It follows session closes and reopens, the seed's tender, status and standby, and the setting. An answer or a follow-up with `to_chief` goes to the profile's Chief, typed under a header that names the asker, the seed and why, and the seed's note keeps the reply without the header. `to_chief` refuses in three cases: while an agent would take the answer, naming it; in a profile with no Chief; and while the Chief has no harness and no session, naming `attn crew set chief`. The phone shows "No agent will get this answer" under a stranded ask's sender (`[data-testid="ask-stranded"]`), and, when the profile has a Chief, its Send reads "Send to Chief" and sends `to_chief`, a one-tap pick too; with no Chief, Send stays. The native sheet shows the same line and offers Send to Chief, for follow-ups too.
- `ask-list`: an agent lists its open asks and those about seeds it tends, then, apart from them, the open asks of the agents it oversees, each with its asker.
- `ask-show`: an agent prints one ask it holds or oversees, with its asker, seed, age and markdown, and "Not your ask" for an overseen one.
- `ask-amend`: an agent adds markdown to an open ask it holds or oversees when the facts change; the ask keeps its place, subject and question keys, and the user sees the addition as an update with its time. Question blocks, a replied ask, a session that may not close the ask, and a relative image from a folder other than the ask's are refused, and the phone gets no second push.
- `ask-re`: `attn ask --re <id>` opens a follow-up to an earlier ask the agent holds or oversees. The new ask keeps a copy of the earlier ask's subject, the user's answer and its time, so it survives the earlier ask being forgotten a day after its reply; an id that is already gone is kept alone, and an ask out of the agent's reach refuses. The answer as attn types it names `attn ask --re <id>`. The phone shows "Follows <subject> · you answered <age> ago" above the subject, folded over the earlier answer: on the phone `[data-testid="ask-follows"]`, in the native sheet the `asks.follows` button, which unfolds `asks.follows.answer`.
- `ask-close`: an agent withdraws an ask it no longer needs, or an overseen ask with `-m "<why>"`; attn notes the reason on the ask's seed and mails it to the asker.
- `ask-oversee`: an agent reaches the asks of the agents below it in its delegation chain, and the Chief every ask in its profile, never another profile's.
- `ask-seed-show`: `attn seed show` lists the seed's open asks above its notes.
- `ask-snooze`: snoozing or waking the agent that holds an ask from the sheet; a snoozed agent's asks wait under Snoozed, leave every open-ask count and send no phone push.
- `ask-markers`: the open-ask chip on the agent's tile header and the marker on its sidebar row.
- `ask-button-motion`: the title bar's asks button, an accent pill with the count while asks are open, pops with an accent glow when a live ask arrives (not for asks already open when the app connects or reconnects) and, under `asks_button_motion` `remind`, again every `asks_button_remind_seconds` while asks wait with the sheet closed. It keeps still while the sheet is open, under `off`, and under Reduce Motion.
- `ask-guidance`: what attn tells agents about asking.

## How to get to it

### People

- ⌘⇧R (`dock.asks`, `native/crates/attn-app/src/keymap.rs`) opens and closes the asks sheet. It opens on the ask of the agent on screen when that agent holds one (the ask the sheet showed last if it is that agent's, else its oldest), else on the ask it showed last, else on the first. The shortcut exists only while asks are on or any ask exists.
- Palette (`native/crates/attn-app/src/palette/commands.rs`): `asks` ("Open asks"), which opens on the same ask as ⌘⇧R.
- Title bar: the asks button, named "N open asks", and the Asks group on home, one row per ask (`native/crates/attn-app/src/asks/view.rs`, `native/crates/attn-app/src/home/mod.rs`).
- In the sheet (`native/crates/attn-app/src/asks/`): the ask list in its rail, the ask's header on one line with its asker, the asker's state, the seed's slug (`asks.seed`, with the seed's title when it differs from the asker's name) and icon buttons named "Copy ask", "Open agent", "Snooze" or, for a snoozed agent's ask, "Wake", and "Show seed" (`asks.open-seed`), which shows the ask's seed in the panel, each ask's questions with single, multiple, "Other…" and text answers, "Add a condition" under a choice question's picks, which opens a field named "Condition on <pick>" (`asks.q.<key>.condition.field`; typing in Other of a one-choice question drops the pick and the field), links to mentioned seeds and to the agents attn knows by their ids, wherever the ask's words name them, the inline markdown of the subject, each prompt and each choice's name and reason (links, bare URLs, bold, italic and code, drawn without their markup; a line that would read as a block shows as written; the answer still reports a choice's label as the agent wrote it, and a press on a link in a choice opens it without picking the choice), the note "Anything else for <agent>?", which waits behind "Add a note" (`asks.note.add`) until it is opened or holds words or files, and shows open on an ask with no question, "Accept all recommended" (shown when two or more questions have a recommendation, and on the phone as `[data-testid="ask-accept-recommended"]`), "Send", "Replied" and "Close asks". An ask's images show from the home's copy and open larger on a press; one with no copy says `[missing image: <alt>]`. A Mermaid diagram too wide to read fitted shows at its size in a box that scrolls, under "Large diagram · 100%" and "Focus diagram", which opens it over the window to zoom and pan; one that cannot draw shows its source under "Diagram failed to render". A table wider than the ask fits its columns as a document's do and scrolls sideways past that. The phone opens a mentioned seed from the same text and returns to the unfinished ask, and draws the same inline markdown. When the seed's tender closed on standby, `asks.from` names it `<label> · on standby`, `asks.resumes` says "Your answer resumes it." (or, when the resume is blocked or `garden.tender_resume` is `watches` or `off`, that the answer waits for it), and the card has no Open agent or Snooze. On a stranded ask, `asks.from` says "No agent will get this answer", or "No agent will get a follow-up" once it is replied. With a Chief in the profile, `asks.send` and `asks.follow-up.send` read "Send to Chief" and send `to_chief`, the note and the follow-up ask what else the Chief should know, `asks.resumes` does not show, and the follow-up's notice says "Follow-up sent to Chief". With no Chief, the line shows and Send stays. Every text of an ask selects with a drag, a double-click or a triple-click and copies with ⌘C: the subject (`asks.subject`), each prose part, each prompt and context, each choice's name and reason (`asks.q.<key>.choice.<n>.name`), and a replied ask's answers and note. A drag selects within one text, also one that starts on a link or a seed's name in the prose; a click on a choice's name still picks it, and a click on a link still opens it. A click on the title bar's asks button, or in the margin around the sheet, closes it. An amendment shows after the ask's parts as `asks.part.<n>`, headed `asks.part.<n>.amended` ("Updated <age> ago"), and leaves the answer started in place. One question is active, the first choice question with no pick when the sheet opens. Its number turns the accent colour (`asks.q.<q>` has the value `active`), and only its choices show keycaps; the other questions keep the keycaps' room. A click in a question makes it active. A pick in a one-choice question, by key or click, moves the active question and the keyboard to the next choice question with no pick. The Quote button (`asks.quote`) floats over a selection of the ask's text. The footer's "Keys" button (`asks.keys`) or ? shows and hides `asks.hints`, which names `1–<n> pick`, `↑ ↓ space move · pick`, `⇥ next question`, `q quote`, `t open command` on an unanswered ask with a command, the letter keys, and, while the panel is open, `⌘⇧] ⌘⇧[ next · previous tab` (with two tabs or more) and `⌘W close tab`. A replied ask's footer has "Follow up" (`asks.follow-up`), which opens `asks.follow-up.field` and becomes "Send follow-up" (`asks.follow-up.send`). Keys: ⌘↩ sends, or sends the follow-up on a replied ask, to the Chief on a stranded ask the Chief takes, f opens a replied ask's follow-up, 1–9 pick a choice of the active question and the number after its last choice puts the keyboard in its Other field, ↓ and ↑ from a choice or a button move the keyboard through its stop's controls in order and stop at either end (a choice question's choices, then "Add a condition" or its field once it has a pick, then Other; a written question's field, then "Use the suggestion"; a file question's files' Remove, then "Attach file"; the note, its files' Remove, then "Attach file"), the arrows in a field move its caret and never leave it, Space picks the focused choice, ⇥ and ⇧⇥ move the active question through the questions and the note and put the keyboard in a written question's field (then its "Use the suggestion" while the field is empty), in a choice question's chosen or first choice (then "Add a condition" or its field once it has a pick, and Other after an open condition field), or in the note, on "Add a note" while the note is closed; ⇧⇥ enters a question at its last control, and past the note or before the first question Tab goes on through the sheet's buttons, q or the Quote button appends the selected passage to the note as `> ` lines and puts the keyboard at the note's end, n opens the note and puts the keyboard in it, a accepts all recommended, c copies the ask as the markdown its agent wrote, with its subject as a heading, each amendment headed `Updated <instant>:` and `Ask <id> from <asker>` last, j and k step through asks, r shows replied asks, o closes the sheet and opens the asking agent, s snoozes or wakes it, g shows the ask's seed in the panel, t opens the ask's first command in a terminal (`ask-commands`), ⌘⇧] and ⌘⇧[ move between the panel's tabs, ⌘W closes the shown tab, Escape closes and keeps the ask shown for the next open.
- On the asking agent's tile header, the chip "Open ask: <subject>" opens the sheet on the oldest ask, and hovering it shows each ask with an Answer button (`native/crates/attn-app/src/asks/view.rs`). Sidebar rows, off-screen shelf entries and rail desktops carry a marker (`native/crates/attn-app/src/asks/view.rs`, `native/crates/attn-app/src/desktop/shelf.rs`, `native/crates/attn-app/src/sidebar/mod.rs`).
- **Settings → Agents and models → Session defaults**: the "Asks" switch (`asks_enabled`, `native/crates/attn-app/src/settings/agents.rs`).
- Where people see what agents do: the title bar's asks button counts open asks except a snoozed agent's, drawn as an accent pill while any are open, and an ask row says "Waiting on you" when its agent is also owed a turn.
- Conditions: the phone shows a replied answer's "Condition: …" under it (`mobile/src/asks/view.ts`) and adds none.
- Answer files: under the note, `asks.files` holds a tile or chip per file (`asks.file.<id>`, value `uploading`, `ready` or `failed`) with its remove button (`asks.file.<id>.remove`), then **Attach file** (`asks.attach`, a file picker). ⌘V anywhere in the sheet attaches copied files, else a pasted image as `Pasted screenshot.png`, while a text paste into a field types it, even beside an image on the clipboard, which attaches only with no field focused (`TextInput::on_paste` and `TextArea::on_paste` in the Rune fork); files dropped on `asks.sheet` attach while `asks.drop` shows. Send reads "Sending…" until every file has uploaded. A replied ask lists its files as chips. The phone names a replied answer's files (`mobile/src/asks/view.ts`). A file question holds its own zone, `asks.q.<key>.files`, with its files and **Attach file** (`asks.q.<key>.drop`), where ⇥ stops. Files dropped on the zone attach to that question; while ⇥ or a click made the file question active, a pasted file and files dropped elsewhere on the sheet attach to it too (the overlay reads "Drop to attach to question <n>"), and otherwise to the note. The answer sends a file question's files as that answer's `attachments`. Source: `native/crates/attn-app/src/asks/attach.rs`, `asks/view.rs`; the daemon refuses an id that is not ready or not owned by the ask, naming the file (`answerFiles`, `internal/daemon/asks.go`).
- Their own shell: `attn ask list --session <id>` and `attn ask close <id> --session <id>`.

### Agents

- `attn ask` (`internal/catalog/content/ask.yaml`, `internal/daemon/commands_ask.go`, `cli/attn/src/commands/ask`), and the tools `ask`, `ask_list`, `ask_show`, `ask_amend` and `ask_close` over `/mcp`: with no subcommand it opens an ask from stdin or `--file`, and takes `--subject`, `--seed` and `--re`. The daemon on the asker's machine reads each local image the markdown shows (resolved against the working directory, or beside `--file`; for a tool, the folder the session started in) and sends the bytes with the ask to the home; an unreadable image or more than 5 MiB of images refuses the ask, and so does an image the app or the phone cannot show: an SVG, a remote, `//` or `data:` URL, a `file://` URL on another host, a file of another type, an anchor, or an HTML `<img>` tag. The refusal points to a `mermaid` block and a local `![alt](path)`. An ask stored before these refusals still reads, lists and shows. The subcommands are `list`, `show <id>`, `amend <id>`, which reads its markdown from stdin or `--file` and sends its images as `attn ask` does, and `close <id>`, which takes `-m <why>` and needs it for an overseen ask. Every form takes `--session` and `--json`.
- `attn seed show <seed>` (`cli/attn/src/commands/seed/render.rs`): an `asks` line per open ask, above the notes.
- `attn agent attachment <attachment-id> --out <path>` (`internal/catalog/content/agent.yaml`, `internal/daemon/commands_agent.go`) downloads an answer's file, as it does a Quick Capture's.
- Launch guidance comes from `internal/prompts/content/ask/rules.md` and `visuals.md`. Launches without tools also get the CLI syntax and example (`cli.md` and `example.md`).
- The ask tool description uses `tool-rules.md`, `permission.md` and `tool-details.md`, which shows only the question block of `example-question.md`. Agents without the launch rules can read them with `skill {reference: ask}`. The catalog generates that reference from the launch rules. `attn ask --help` uses `help-rules.md`, `permission.md`, `visuals.md` and `help-details.md`, which holds the whole `example.md`.
- See Follow progress and recover in the [delegation reference](../../../../internal/prompts/content/skills/attn/references/delegation.md). The other ask prompts include the withdrawal mail and seed note (`tellWithdrawnAsk`, `internal/daemon/asks.go`), and the answer as attn types it (`internal/prompts/content/ask/answer.md`, `entry.md`, `entry-picked.md`, `entry-recommended.md`, `entry-other.md`, `entry-condition.md`, `entry-unanswered.md`, `note.md`, `files.md`, with each file line from `internal/prompts/content/session/quick-capture-file.md`), and the notice when a default falls due (`internal/prompts/content/ask/default-due.md`).

### Triggers

- A default falling due: the one-minute `ask_default_due` tick (`internal/daemon/ask_defaults.go`) queues the notice in the addressee's inbox, classed as a reminder for `garden.tender_resume`.
- The user's answer is user input in the addressee's inbox. A ring types the answer into the conversation without waiting for the agent's turn to end (`internal/daemon/asks.go`, `internal/daemon/inbox_delivery.go`).

## Driving it

Preconditions:

- Use the baseline instance with its app, launched as [../SKILL.md](../SKILL.md) says. Then run `bridge wait '{"target":{"key":"home"}}'`. On Linux, run every command that reaches the app inside one `xvfb-run -a -s '-noreset -screen 0 1600x1000x24' bash -c '…'`.
- Make a proof folder with `P=$(mktemp -d /tmp/drive-attn-asks.XXXX) && echo "export P=$P" >> $DRIVE_ENV`.
- Make an agent folder with `A=$(mktemp -d /tmp/drive-attn-asks-agent.XXXX) && echo "export A=$A" >> $DRIVE_ENV`. Save `ask.md` (`:::question-text`, `Which day ships it?`, `:::`, one per line) in it, and this fixture as `$A/.attn-mock-agent.json`:

## Contexts

- **Durability across restarts**: open asks, their drafts, answers and the answer's inbox item are the daemon's records and survive app, daemon and machine restarts. A draft's last 0.4 s of writing before the app quits is not saved. An answer's files stay in `<data-dir>/attachments/<profile>/` after the ask is forgotten, so the file lines in seed notes stay valid. A file the ask never sent (still staged or ready, such as one pasted into a draft or removed while uploading) is discarded when the ask's row goes, by any path, and its file is removed at once; the next start removes any the daemon missed. Start-up recovers a file whose upload a restart cut short, as for Quick Capture. The home keeps an ask's images under `<data-dir>/asks/<ask>/` until the ask's record goes. Each time the daemon starts, it copies any image an ask shows that has no copy yet, from its file on the home; this covers asks opened before attn copied images.
- **Outposts**: `attn ask` on an outpost reads the images there and the home keeps the copy, so the sheet shows them. A file link in an outpost's ask opens from the machine its reference names (`ask-references`). The sheet shows answered asks for a day.
- **Linux**: `attn ask` works the same where the daemon and CLI run on Linux. `dock.asks` is Ctrl+Alt+R there, and Ctrl+Enter sends from the sheet.
- **Performance and idle cost**: an ask's markdown is at most 64 KiB, and its images at most 5 MiB together. The sheet loads each image once per ask it shows. An open, idle sheet repaints nothing (seed `s-g87385`'s C4). When a change touches the sheet's rendering, check it for repaints with `docs/internal/perf-testing.md`.
- **Harnesses**: the guidance tells every harness, with attn's tools or without, to open an ask for any decision only the user can make instead of asking in the conversation or in the harness's own question tool, whether or not it can keep working meanwhile, and to show what the decision turns on with the smallest fitting visual. The answer arrives as the user's message in every harness, so harness auto-mode reviewers count an approval in it as the user's.
- **Keyboard and native input**: ⌘⇧R opens the sheet with the keyboard on the active question. The sheet is modal: Tab stays in it and the window behind it takes no input. While a panel shell holds the keyboard (`ask-commands`), every key but the Asks chord, ⌘↩ and the tab chords is the shell's. ⇥ moves the active question even from inside an answer field, as the sheet's keys above say; links in the ask after its first question take the keyboard only by a click. The keys j, k, a, c, f (on a replied ask), r, o, s, g, t, q, n, ?, 1–9, ↑, ↓ and Escape work while focus is not in a text field, and ⌘↩ sends from anywhere in the sheet. A press or drag on an ask's text moves the keyboard to the sheet, off any answer field, so the letters and ⌘C work after it.
- **Compatibility across versions**: an agent keeps the asks setting it launched with. When you turn asks on, only agents launched afterward can ask. An agent launched earlier refuses `attn ask` until the agent is relaunched, so relaunch the agent instead of toggling the setting again.
- **Large gardens**: a mention opens in the panel whether or not it is in the Garden's pushed list; the panel reads its document with `seed_document_get`. Its "Reveal in Garden" shows only when the Garden holds the seed or its profile is the selected one.
- **Phone**: the daemon sends no ask push while the asker is snoozed (`askNote`, `internal/daemon/phone_push.go`), and none for an amendment (`ask.amended`); an ask's push shows its subject without its inline markdown (`ask.Plain`, `internal/ask/plain.go`); the phone shows an amendment as a part headed "Updated <age> ago". The phone's own asks list still shows a snoozed agent's asks; it has no snooze. The phone names a replied answer's files but cannot attach any, shows a file question as "Answer this in the native app.", and shows a replied answer's condition but cannot add one.
- **Flow**: in queue flow, the title bar's asks button counts open asks except a snoozed agent's. Clicking it or pressing ⌘⇧R opens the sheet. An ask row whose agent is owed a turn says "Waiting on you".

## Gotchas

- A pulse lasts under 1.5 s and only the glow's element (`glow.<n>` under `titlebar.asks.motion`) shows it in `bridge tree`. With the default 60 s reminder, a window with an open ask is never fully at rest: one wake stays armed for the next reminder.

- An answer is user input, so attn types it only after 30 seconds of quiet in the agent's terminal. `wsctl input` to the asking agent restarts that wait.
- `attn ask --seed <id>` needs the asker to tend the seed. attn refuses it from an agent that has not claimed the seed, with `nobody is tending <seed> ... tend it first`.
- attn types a multi-line answer as one bracketed paste, so the mock sees one prompt. Keep `answered the ask` as the fixture's first turn: the mock tries turns in order, and the rest of the answer carries the user's own words, which can match a later turn.
- The sheet's letter and number keys act only while focus is outside a text field. ⌘⇧R and `j` put focus on the active question's choice, where they work, or in a written answer's field, which takes the letter as text, so press `asks.part.0` or any other text of the ask first. With the sheet closed, the letter reaches the agent's terminal and restarts the 30-second quiet wait.
- The `dock.asks` shortcut, the palette command and the sidebar icon exist only while asks are on or some ask exists. An instance with asks turned off and no asks shows none of them. Their absence there is not a missing way in.
- Working but wrong: after sending, the sheet moves to the next open ask, or to its empty state, with no confirmation that the answer reached the agent. The proof is the agent's screen, not the sheet.
- A link the ask's markdown writes is keyed by its destination, so `bridge press '{"target":{"key":"home:~/notes/plan.md"}}'` opens it, though the receipt reads `landed "b1"` (seed `s-ykn8bz`'s C1 run). A seed's or an agent's id that the ask's words link has not been pressed that way: reach it with Tab and press Enter, or press the real mouse on the link's `bounds` as [markdown.md](markdown.md) says.
