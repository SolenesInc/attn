# Markdown tiles

Open a markdown file in a tile, rendered and live as the file changes. An
agent shows the user a plan, a report or a design this way, beside itself. The
user opens files with ⌘P, from a terminal link or from their own shell. The
tile follows edits on disk, so a document the agent keeps writing stays
current while the user reads it. For review notes on a markdown tile, see
[annotations.md](annotations.md).

## Sub-features

- `file-open`: `attn open <file.md>` docks a markdown tile beside the caller, or beside the active tile when no session calls. A seed id opens a seed tile instead ([garden.md](garden.md)).
- `file-opener`: ⌘P lists recent files on an empty query, fuzzy-searches the active agent's folder, and browses folders for a query starting with `/`, `~`, `./` or `../`.
- `recent-files`: files opened before, the most used and most recent first. Picking one returns to the file's tile when that tile is still open.
- `markdown-render`: headings, tables, alerts, code with highlighting, images, Mermaid diagrams and frontmatter.
- `live-reload`: the tile re-reads its file when the file changes.
- `terminal-link`: ⌘-click a markdown path in a terminal to dock it, bound to the session that terminal shows ([terminals.md](terminals.md)).
- `document-focus`: show the document alone on the desktop, and return with Escape.
- `open-in-editor`: open the active agent's folder in the user's editor.
- `review-document`: experimental, behind `code_review_enabled`. A markdown file with `attn: review` in its frontmatter is a review document. Its tile also receives a bundle: each `### path:from-to` stop resolved to rows of the file now with the change from base, its notes, flows and problems. The tile renders it in the frame its `frame:` picks (see `review-frames`). The Brief frame shows a summary of the change, each stop as code rows with line numbers, the change from base and agent notes under their line, and the Not shown list. A keyboard cursor walks it.
- `review-frames`: a review document opens in the frame its `frame:` picks, and `1`, `2` and `3` switch, keeping the cursor's stop and line. Walkthrough shows the document as a script beside the file view of the current stop. Map draws a mermaid `sequenceDiagram` (participants, actors and messages) beside the code of the current message's stop; with `mermaid before` and `mermaid after` fences, `b` switches between them, also to a side that ties no message to a stop. A frame the document cannot fill is left out: Walkthrough needs a stop, Map a drawn diagram with a `%% stop:` message. A diagram with any other line stays a mermaid figure and is a problem in `attn review check`.
- `review-file-view`: from a review document, open any file whole with the change drawn in and the stop's range marked, go back through the files opened, and search the repository (files by name, lines by `git grep`), on the machine that holds the document.
- `review-marks`: on a review document, notes and questions on lines of a stop or the file view, and a send with a verdict. A note waits for the send. A question goes to the tile's session at once, stays in the draft, and the agent answers it with `attn review answer`; the answer shows under the line. The send lists the marks in reading order with their file, lines and quoted code, then the edits ([`review-edits`](#sub-features)), then the verdict, as one message. A mark is anchored to its lines at the review's head and stays on them when the file changes; when any of those lines changed after head it shows under "Moved notes" at the end of the document and goes out labelled as moved. A delivered send records the head the user read, so the next `attn review start` takes it as the base.
- `code-navigation`: behind `code_review_enabled`. A shown review document starts a language server for each language its files are in, on the machine that holds the document, and the bundle's `navigation` lists each language's state (`starting` with the server's progress text, `ready`, `missing`, `failed`). `code_nav` answers definition, uses and type for a position, and the reader asks it with `f`, `r` and `h` on the line under the cursor. An answer that takes over 1.5 s while the cursor moves is offered in a list instead of moving the view. A definition outside the repository opens read-only. A server stops after `code_navigation_idle_stop_seconds` (300) with no review shown, including when an outpost loses its home's bridge, and a server a killed daemon left is reaped at the next start. A server that rejects `initialize` fails at once with its reason and leaves no process.
- `code-navigation-setup`: behind `code_review_enabled`. When a shown review has a language whose server is `missing` or `failed`, the key line offers `s set up` and `x not here` after that language's state; a failed state shows its reason. `s` sends `code_nav_setup` and the home starts a delegation on the review's machine, in the review's repository, with the user's delegation fallback or else their new-session harness, whose seed holds the brief (`content/code-navigation/setup.md`). The reply waits until the agent runs, so a launch failure shows in the key line's note with its reason. While that session exists the key line shows `<language> setting up in <session>`, a link that shows the session. A passing `attn nav check` turns the state `ready` in the open tile. `x` sets `code_review_setup_offer_<local|outpost-id>_<repository>` to `off`, which hides the offer for that repository; `s` still works and `x` again clears it.
- `review-document-stops`: a stop whose path ends in `.md` renders its range as a document, block by block. Changed blocks are marked; a light rewording marks its changed words, diffed over the rendered words; a block where more than half the words changed shows the old text struck above the new.
- `review-edits`: on a review document, `i` edits what the cursor is on and saves it to the file on the machine that holds it, against the hash the text was read with; a file that changed underneath is refused and nothing is written. The edit is listed under its lines, and `u` writes the newest edit's old text back. An edit stands between the lines at the review's head around it, found as marks are, and every view of its file reads it again after a save or an undo; when its text is no longer there, it shows under "Moved notes", where removing it drops it from the review without writing, and `u` does not reach it. The send numbers the edits on from the notes, each with the text before and after. A document stop on the home opens in an editor tile.

## How to get to it

### People

- ⌘P (`file.open`, `app/src/shortcuts/registry.ts`) opens the opener (`app/src/components/palette/MarkdownOpener.tsx`). Inside a focused editor tile, ⌘P opens that tile's note finder instead ([notebook.md](notebook.md)).
- Palette (`app/src/application/useAppCommands.tsx`): `open-markdown-file` ("Open a markdown file"), and `open-in-editor` ("Open in editor"), offered while an agent with a local folder is on screen (`app/src/application/useOpenInEditor.ts`).
- In a terminal, ⌘-click on a `.md` path (`app/src/components/GhosttyTerminal.tsx`).
- Tile header (`app/src/components/SessionTerminalDesktop/DesktopDockTile.tsx`): "Focus document" (also ⌘⇧↩, `terminal.toggleMaximize`), which a focused document replaces with "Return to row", and "Close tile". The tile's row in the sidebar (`app/src/components/SidebarRows.tsx`) has a "Close <title>" button that takes clicks while the pointer is over the row.
- In the document (`app/src/components/MarkdownReader/index.tsx`): a fragment link scrolls the tile. Images open in a lightbox.
- In a review document (`app/src/components/ReviewReader/ReviewReader.tsx`), with focus in the tile: ↑/↓ by line in code and by block in prose, ←/→ by stop, Enter opens the file at the cursor, `e` shows 10 more lines around the stop, `z` fills the tile with the file, `/` searches, ⌃o goes back, Escape closes the search, the key sheet or the file view, `?` shows the keys. ⇧↑/⇧↓ select several lines, `c` writes a note on them and `a` asks a question (Enter saves, ⇧Enter adds a line, Escape cancels); in the Walkthrough they work on the stop's file. `i` edits the selected lines, else a whole string or comment of several lines, else the line; in a document stop, the block as markdown. In the edit box ⌥↑/⌥↓ take in a line, Enter saves one line and ⌘Enter several, Escape cancels. `u` on an edited line undoes the edit. In a document stop, `o` or the stop's "editor" button opens the file in an editor tile rooted at the repository, on the home only. ⌘Enter opens the send sheet: it lists the marks, then the edits, and takes the verdict with `a` (approve), `r` (request changes) or `c` (comment); Enter sends and Escape returns to the review. In the file view, ↑/↓ and PageUp/PageDown move, ←/→ go to the previous or next change. A click on a row, a file in the summary or a Not shown entry moves the cursor there or opens it; a stop's "file ↵" button opens its file. The key line at the bottom of the tile lists the frames and the keys for the current view. `1`, `2` and `3` switch frames. In the Walkthrough, ↑/↓ move in the file, ←/→ go to the previous or next stop, `z` hides the script, and ⌃o and Escape return to the stop's file. In the Map, ←/→ go to the previous or next message with a stop, `b` switches between before and after, and the other keys work on the stop beside the diagram. On a line of code, in a stop or the file view, `f` labels each name on the line and goes to the definition of the one whose label is typed (on a definition it lists the uses), `r` lists the uses and `h` shows the type; a line with one name skips the labels. A list takes ↑/↓, PageUp/PageDown and Enter, and Escape closes it, cancels the labels or drops a question on its way. The key line shows each language's server state, with what a loading one is doing. For a language with no working server, `s` starts an agent that sets one up, and `x` stops or restores the offer. Selecting text and typing still opens a comment ([annotations.md](annotations.md)).
- Settings: the editor command (`editor_executable`) that "Open in editor" runs. Without it, "Open in editor" runs `$EDITOR` or `$VISUAL`.
- Where people see what agents do: the tile an agent opens docks beside the agent's tile and follows the file as the agent writes it.
- Their own shell: `attn open <file.md> [--session <id>]`.
- The user guide: `attn guide code-review` (`docs/guide/reference/code-review.md`) covers turning the review on, the frames, the keys, marks, the send, and code navigation with its setup.

### Agents

- `attn open <file.md|seed-id> [--session <id>]` (`cmd/attnd/main.go`): a relative path resolves against the folder `attn` runs in. The tile docks beside the caller, or beside the tile of `--session`.
- `attn review start <document> [--base <commit>]` (`cli/attn/src/commands/review.rs`) snapshots the working tree of the repository it runs in as head and writes `frame`, `repository`, `base` and `head` into the frontmatter, creating the document when it is missing. `attn review check <document>` prints each problem with its line and the fix, and exits 1 when there are any. `attn open` on a review document prints the same problems as `attn open: warning:` lines and still opens the tile. `attn review answer --doc <document> <question-id> -m <answer>` stores the answer to a question the user asked; the question's message gives the agent this command. With `code_review_enabled` off, `attn review` refuses and names the setting.
- `attn nav` (`cli/attn/src/commands/nav.rs`): `status` lists the server for each language of the repository it runs in and the running servers with their memory, `check <path>:<line>` asks for the definition of each name on that line and passes on the first answer that is not the asked name itself, `link <program> [--as <name>]` and `unlink <name>` put a server binary in `<data-dir>/code-navigation/bin`, `set <language> <json>` and `rm <language>` write or remove the repository's definition in `code_navigation_<origin>_<language>`. With `code_review_enabled` off, each refuses and names the setting.
- Prompts: `attn skill --reference markdown` (`internal/prompts/content/skills/attn/references/markdown.md`), named in the attn map as "Show the user a markdown document" (`internal/prompts/content/session/attn-map.md`), and `attn open <plot>` in the seed craft (`internal/prompts/content/resources/seed-guide.md`).
- Prompts: `attn skill --reference review` (`internal/prompts/content/skills/attn/references/review.md`) teaches presenting a change: when to present, the base for `attn review start`, what a review contains, the frame to pick, answering a question and acting on each verdict. A session launched with `code_review_enabled` on finds two rows for it in its attn map (`internal/prompts/content/session/attn-map-review.md`): "Present a change for the user to review", and "Set up code navigation in a review for a language with no working server". The question and the sent review arrive through the templates in `internal/prompts/content/annotations/` and repeat the commands.
- Prompts: `attn skill --reference code-navigation` (`internal/prompts/content/skills/attn/references/code-navigation.md`) says how to find, install, link and define a language server. It is the setup agent's guide, and the guide for anyone setting one up by hand.

### Triggers

- An open markdown tile re-reads its file when the file changes on disk, and shows an error when the file goes away or grows past 1 MiB (`internal/daemon/tilecontent.go`).
- An open review document also gets a new bundle when a file one of its stops shows changes (`internal/daemon/tile_documents.go`).
- The file view and search ask the daemon with `review_file` and `review_search` (`internal/daemon/review.go`). With `code_review_enabled` off, both refuse and name the setting.
- An edit sends `review_edit` with the file's path, the hash it was read with, the lines it replaces and the text; it runs on the document's machine and writes through `fsdoc.Store.Write` (`internal/review/file.go`). A changed file answers `conflict` and is left untouched; a file over 2 MiB is refused naming the limit. With `code_review_enabled` off it refuses and names the setting. The edit is an `edit` annotation with `edit_was` and `edit_now`.
- A question and a review go out through `markdown_annotations_submit`: `only_ids` asks the named questions at once, `verdict` and `head` send the review (`internal/daemon/ws_markdown_annotations_submit.go`). After a delivered review the daemon sends `review_sent` to the document's machine, which writes the sent ref. `review_answer` stores an answer and pushes `desktop_tile_content` with a new `annotations_generation`, and the tile re-reads the draft. With `code_review_enabled` off, `only_ids`, `verdict` and `review_answer` refuse and name the setting.
- `code_nav_setup` from the reader's `s` (`internal/daemon/code_nav_setup.go`) starts the setup delegation; the home records the setup's session per host, repository and language in its database and adds it to the bundle's navigation as `setup_session_id` when it sends the tile, so the link survives a home restart. With `code_review_enabled` off it refuses and names the setting.
- Showing a review document, and `attn review start`, start its language servers; a review leaving the watch set releases them and arms the idle stop (`internal/daemon/code_nav.go`, timer `code-nav-idle-stop`). A server whose state changes bumps the document's bundle. Daemon start reaps servers left in `<data-dir>/code-navigation/servers`.

## Driving it

Preconditions:

- Use the baseline instance with its app. Check that `bridge --launch --wait-ready ping` answers, then run `bridge dismiss_whats_new` to dismiss What's new.
- Make a proof folder with `P=$(mktemp -d /tmp/drive-attn-markdown-proof.XXXX) && echo "export P=$P" >> $DRIVE_ENV`.
- Make an agent folder with `A=$(mktemp -d /tmp/drive-attn-markdown.XXXX) && echo "export A=$A" >> $DRIVE_ENV`. In it, save `notes.md` (`# Drive notes` and a line of text), `second.md` (`# Second file`), and `rich.md` (frontmatter with `type: note`, a `# Rich drive` heading, a `> [!NOTE]` alert and a fenced `mermaid` block holding `graph LR; A-->B`). Save this fixture as `$A/.attn-mock-agent.json`:

```json
{"version": 1, "turns": [
  {"includes": "show-notes", "actions": [
    {"type": "attn", "args": ["open", "notes.md"]}]}
]}
```

- Start the agent on the current desktop with `wsctl add-session --cwd $A --agent claude --label md-agent --id md-agent --place`. `<agent>` is its `runtime_id` in `wsctl list`.

- **An agent shows a file.** Run `wsctl input --id <agent> --text "show-notes" --enter`. `./attn agent peek md-agent` shows `opened ` and an absolute path ending in `/notes.md`. In `wsctl list`, the current desktop's `tree_json` holds a tile whose `tile_kind` is `markdown` and whose `tile_params` is that path, beside the agent. `bridge dom_wait '{"selector":"[data-tile-kind=\"markdown\"] .md-reader-doc","textIncludes":"Drive notes","timeoutMs":5000}'` matches.
- **The tile follows the file.** Run `printf '\nA new line.\n' >> $A/notes.md`. `bridge dom_wait '{"selector":"[data-tile-kind=\"markdown\"] .md-reader-doc","textIncludes":"A new line","timeoutMs":5000}'` matches.
- **From the person's shell.** Run `./attn open $A/rich.md`. It prints `opened <A>/rich.md` and exits 0. A second markdown tile docks beside the active tile. `bridge dom_wait '{"selector":".md-frontmatter","timeoutMs":5000}'` and `bridge dom_wait '{"selector":".markdown-mermaid","timeoutMs":10000}'` match, and `bridge dom_text '{"selector":".md-frontmatter"}'` reads `type:` and `note`. `./attn open $A/second.md --session md-agent` docks `second.md` beside the agent instead.
- **The opener with ⌘P.** Select the agent for setup with `bridge select_session '{"sessionId":"md-agent"}'`. Run `bridge native_key '{"key":"p","modifiers":["command"]}'`. `bridge markdown_opener_get_state` shows `open: true` and, on the empty query, a row for each file opened above in `rows`, ranked by use and recency, not by the order you opened them. Run `bridge native_text '{"text":"secnd"}'`: the rows include `second.md`, found by fuzzy search in the agent's folder. Press Enter: the opener closes, no third copy of `second.md` docks, and `desktop.view.activeLeafId` in `bridge get_session_ui_state '{"sessionId":"md-agent"}'` is the `tile_id` of the `second.md` tile in `tree_json`.
- **Path mode.** Press ⌘P and type `~/`: `markdown_opener_get_state` lists your home folder's entries. Press Escape: `open` is false.
- **From the palette.** Open the palette (⌘⇧K, wait for `[role="combobox"][aria-label="Commands"]`), type `Open a markdown file`, press Enter: `markdown_opener_get_state` shows `open: true`. Press Escape.
- **From a terminal link.** ⌘-click a `.md` path printed in a shell, as the recipe in [terminals.md](terminals.md) does: the tile that docks carries the clicked terminal's session id as its `tile_session_id` in `tree_json`.
- **Focus the document.** Read the `notes.md` tile's `tile_id` from `tree_json` as `<notes-tile>`. If the tile is a collapsed strip, click its `Expand notes.md` button natively and wait for `[data-pane-id="<notes-tile>"] .md-reader-doc`. Click `[data-pane-id="<notes-tile>"] .md-reader-doc` natively to make it active, then run `bridge native_key '{"key":"Enter","modifiers":["command","shift"]}'`. `desktop.view.maximizedPaneId` in `bridge get_session_ui_state '{"sessionId":"md-agent"}'` names the tile. Press Escape: `maximizedPaneId` is null again. The same tile's `[aria-label="Focus document"]` button, clicked natively, does the same.
- **In the document.** Images render only in a document under the home folder, as Gotchas records, so put this document there: `printf '# Image doc\n\n[Down](#bottom)\n\n![pic](drive-pic.png)\n\n<eighty lines of filler>\n## Bottom\n' > ~/attn-notebook-<name>/drive-imgdoc.md`. Put a 200×100 PNG named `drive-pic.png` beside it. Run `./attn open ~/attn-notebook-<name>/drive-imgdoc.md` and read the new tile's `tile_id` as `<img-tile>`. Click `[data-pane-id="<img-tile>"] img[alt="pic"]` natively: `bridge dom_wait '{"selector":".md-lightbox[role=\"dialog\"]","timeoutMs":5000}'` matches. Escape closes the lightbox. Read `bridge dom_bounds '{"selector":"[data-pane-id=\"<img-tile>\"] #bottom"}'`, click `[data-pane-id="<img-tile>"] a[href="#bottom"]` natively, and read the bounds again: the heading's `y` moves up into the tile.
- **Close the tile.** Click `[data-pane-id="<notes-tile>"] [aria-label="Close tile"]` natively (point from `bridge dom_native_point`): that tile leaves `tree_json`, and the file stays on disk. Open it again with `./attn open $A/notes.md` and read its `tile_id` again as `<notes-tile>`. `<desktop>` is `arrangement.currentDesktopId` in `bridge get_state`. Move the pointer over `[data-testid="sidebar-tile-<desktop>-<notes-tile>"]` with `bridge native_mouse` and `"action":"move"`, then click `[data-testid="close-tile-<desktop>-<notes-tile>"]` natively: that tile leaves `tree_json` too.
- **The file goes away or grows too large.** Read the `second.md` tile's `tile_id` from `tree_json` as `<second-tile>`. If the tile is a strip, expand it (`[aria-label="Expand second.md"]`, natively). Then run `mv $A/second.md $A/second.md.bak`: `bridge dom_text '{"selector":"[data-pane-id=\"<second-tile>\"] .desktop-dock-tile-body"}'` reads `file not found: <A>/second.md`. Move the file back: the tile reads `Second file` again. Append more than 1 MiB to the file: the tile reads `file is too large to preview (<bytes> bytes, max 1048576)`. Write `# Second file` back: the document returns.
- **Open in editor.** Run `./attn settings set editor_executable "touch <A>/editor-opened && echo"`, `<A>` written out. Select the agent, open the palette, type `Open in editor`, press Enter: re-run `test -f $A/editor-opened` until it succeeds, with a deadline that fails the run. Run `./attn settings set editor_executable ""` to restore the setting.
- **The editor setting in Settings, and its fallback.**
  - Press ⌘, and click `[data-testid="settings-nav-desktop"]` natively, click `#settings-editor-exec` natively, type `touch <A>/editor-opened2 && echo` and press Enter: `./attn settings get editor_executable` prints it, and "Open in editor" from the palette creates `$A/editor-opened2`. Set `editor_executable` back to empty.
  - For the fallback, append `export EDITOR='touch <A>/editor-env-opened && echo'` to the env file, quit the app with `./attn instance stop-app` and launch it again with `bridge --launch --wait-ready ping`: with `editor_executable` empty, "Open in editor" creates `$A/editor-env-opened`. Append `unset EDITOR` afterwards.
- **A review document.** Run `./attn settings set code_review_enabled true`. Make a clone with an uncommitted change, such as `git clone -q --no-checkout . $A/subject && git -C $A/subject checkout -q <commit> && git -C $A/subject reset -q --mixed <commit>~1`. From `$A/subject`, `./attn review start $A/review.md --base <commit>~1` prints `created`, the head over the base, and the next commands. Below the frontmatter, write a `### path:from-to` stop for one changed file with a range past its end, and list every other changed file under `## Not shown`. `./attn review check $A/review.md` prints `L<n>: the stop … ends past the file (… lines at head). Use …` and exits 1. `./attn open $A/review.md` prints `opened` and the same line after `attn open: warning:`, exits 0 and docks the tile. Fix the range: both print no problem. `./attn review start $A/review.md` again prints a new head over the same base.
- **Walk a review by keyboard.** With the fixed review document open and `code_review_enabled` on, click `[data-tile-kind="markdown"] .review-doc` natively. `bridge dom_wait '{"selector":"[data-review-stop-head]","timeoutMs":5000}'` and `bridge dom_wait '{"selector":"[aria-label=\"Review keys\"]","timeoutMs":5000}'` match. Press ↓ with `bridge native_key '{"key":"ArrowDown"}'`: `bridge dom_text '{"selector":".review-cursor"}'` moves to the next row. Press → to reach the next stop, then Enter: `bridge dom_wait '{"selector":"[data-review-file-view]","timeoutMs":5000}'` matches and its header names the path. Press `z`: the file view gets `.review-file-view--filled`. Press `/` and type a word from the change with `bridge native_text`: `[role="dialog"][aria-label="Search the repository"] [role="option"]` lists files and hits. Press Enter to open one, then ⌃o: the earlier file is back. Press Escape until `[data-review-file-view]` is gone.
- **Switch a review's frames.** Add a fence to the fixed review document: ```` ```mermaid after ````, `sequenceDiagram`, `a->>b: <text>`, `%% stop: <the stop's path:from-to>`, ```` ``` ````, and set `frame: map` in its frontmatter. `./attn review check $A/review.md` prints no problem. Close the tile and run `./attn open $A/review.md`, because an open tile keeps its frame: the tile opens with `[data-review-flow]` drawn and `.review-map-detail .review-stop` showing the stop. Press `2`: `.review-frame--walkthrough [data-review-file-view]` matches and `.review-stop--current` is the same stop. Press `z`: `.review-frame--script-hidden` matches. Press `1`: `.review-doc .review-cursor` is inside that stop. Add a `loop x` line to the fence: `attn review check` prints two problems, that line and the `frame: map` line, the tile's key line lists only Brief and Walkthrough, and the fence renders as `.markdown-mermaid-frame`.
- **Ask a question, answer it and send the review.** With the review document open, bound to a session (`./attn open $A/review.md --session <id>`), click `.review-doc` natively, press → to reach a stop and ↓ to a row. Press `a`: `[role="dialog"][aria-label="Ask a question"]` names the place and `Sent to <session> at once`. Type a question with `bridge native_text` and press Enter: the session receives `# A question from the user's review` with the quoted lines and `attn review answer --doc <A>/review.md <id> -m "<your answer>"`, and `.review-mark` reads `Asked — waiting for the answer`. Run that command with an answer: `.review-mark-answer` shows it with no key pressed. Press ⇧↓ on another row, then `c` and write a note. Press ⌘Enter: `[aria-label="Send the review"]` lists both marks with request changes picked. Press `a`, then Enter: the session receives `# Review`, both marks in reading order, and `Verdict: approve.`; the marks leave the tile. `./attn review start $A/review.md` again prints the head just reviewed as the base.
- **Edit a review's file and undo it.** With the review document open and bound to a session, click `.review-doc` natively and move to a changed row. Press `i`: `[role="dialog"][aria-label="Edit the file"]` names the path and `line <n>`, or `this string, <n> lines` inside a string of several lines. Change the text and press Enter (⌘Enter for several lines): the file on disk has the new text, the stop shows it, and `.review-mark--edit` reads `you edited`. Edit the file from the shell, then press `i` on the same line, change it and save: the box says nothing was written and the file keeps the shell's text. Press Escape, then `u` on the edited line: the file has its old text back and `.review-mark--edit` is gone. Edit once more and press ⌘Enter: the sheet lists `Your edits, saved to the files`; send it and the session receives the edit with `It was:` and `It is now:`. ## Contexts

- **Durability across restarts**: a markdown tile is part of its desktop and comes back after any restart, re-reading the file. Recent files are kept too. The file itself is the source, so a tile shows whatever is on disk now.
- **Linux**: `attn open` works the same where the daemon and CLI run on Linux. The opener is Ctrl+Shift+P there (`LINUX_SHORTCUTS`).
- **Outposts**: a markdown tile reads, watches and loads images from the machine that holds its file. `attn open` from an outpost agent, and a markdown file it sends, open the outpost's file, never a home file at the same path. Links to other markdown files open on that outpost; other local links name it. Drive it with `./scripts/test-go.sh --packages -run TestAMarkdownTileFromAnOutpostShowsTheOutpostsFile -v ./cmd/attnd`. A draft on an outpost tile is keyed by its host and path (document URI `attn://file/<path>?host=<id>`), apart from a home draft at the same path. Files an outpost agent sends or edits, also while the outpost is away, show in `recent_files` with `host` and in ⌘P as `<path> on <outpost>`, open there, and are never stat'ed or pruned by the home. Drive both with `./scripts/test-go.sh --packages -run TestAnOutpostsFilesKeepTheirMachineInRecentsAndDrafts -v ./cmd/attnd`. A review document on an outpost resolves, opens files and searches on the outpost; on Linux, drive it with `./scripts/test-go.sh --packages -run TestTheFileViewAndSearchOfAnOutpostsReviewReadTheOutpostsRepository -v ./cmd/attnd`. A question on it reaches the outpost agent, the agent's `attn review answer` lands in the outpost's draft, and a sent review writes the sent ref in the outpost's repository; on Linux, drive it with `./scripts/test-go.sh --packages -run TestAnOutpostAgentsReviewTakesItsAnswerAndRecordsItsSendOnTheOutpost -v ./cmd/attnd`. An edit of an outpost review's file writes the outpost's file and never a home file at the same path; on Linux, drive it with `./scripts/test-go.sh --packages -run TestAnEditOfAnOutpostReviewWritesTheOutpostsFile -v ./cmd/attnd`. The editor tile is not offered for an outpost's document. attn refuses ⌘-click on a path in a terminal on an outpost, and "Open in editor" for an agent on an outpost, with `<path> is on <outpost>; opening files on an outpost isn't supported yet`.
- **Profiles**: tiles open on a desktop of the caller's profile. Without a session, a tile opens on the current desktop of the profile used most recently.
- **Performance and idle cost**: each open markdown tile keeps checking its file while it is open, so tiles nobody reads still cost a little. Close them. attn refuses files over 1 MiB and names the size and the limit. Large Mermaid diagrams scroll instead of shrinking (`app/e2e/mermaid-diagram.spec.ts`).
- **Harnesses**: every harness opens files with the same `attn open`.
- **Keyboard and native input**: ⌘P opens the opener from anywhere except a focused editor tile. In the opener, use the arrow keys, Enter and Escape. ⌘⇧↩ focuses the active document and Escape returns.

## Gotchas

- With several documents docked, inactive tiles can collapse into strips, and their document bodies are absent from the DOM. Expand the target tile before clicking its body or header controls. A collapsed strip's `[data-pane-id]` holds only the file name, so reading the tile's document text or error shows only `second.md`. Scope focus and close controls to the intended `tile_id`, because a broad `[data-tile-kind="markdown"]` selector can pick a collapsed tile whose controls are not visible. Sidebar tile test ids include both the desktop id and the tile id.
- `attn open` reads a bare name starting with `s-` as a seed id, so `attn open s-notes.md` is refused as `"s-notes.md" is not a seed id`. Pass `./s-notes.md`.
- Opening the same file twice returns to the file's tile instead of docking a copy. A recipe that counts tiles after a second open sees one. Opening the same file through `/tmp` and `/private/tmp` still creates two tiles, because path-alias reuse is not fixed yet. Keep the path spelling consistent when checking reuse.
- A path the agent resolves from a relative name comes from the folder it runs in. On macOS `/tmp` is `/private/tmp`, so compare file names, or resolve both sides with `realpath`.
- On an empty query the opener lists only files opened before. A fresh instance shows none until something is opened.
- Without the app, `attn open` still places the tile in `tree_json`. Only the app renders it. Prove rendering with `bridge`, not the CLI.
- `bridge capture_screenshot` shows the rendered document, but Mermaid renders after the text. Wait for `.markdown-mermaid` before capturing.
- The app checks a path and reads a local image through a file scope limited to the home folder. A `.md` path under `/tmp` printed in a terminal is plain text to ⌘-click, and an image beside a document under `/tmp` renders as an empty 1×1 box. `attn open` itself opens a document anywhere. Drive the terminal link and images with files under the home folder, such as the instance's `~/attn-notebook-<name>`.
- Working but wrong: a file that grows past 1 MiB, or is deleted, turns the open tile into an error, and the tile recovers on its own once the file is back under the limit. "Open in editor" opens the agent's folder, not the document in the active tile.
