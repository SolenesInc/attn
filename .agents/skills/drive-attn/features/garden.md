# Garden

The garden is the work tracker: seeds planted, tended and harvested. A seed is
the unit agents hand off, work on and stay organized with, and a plot is a seed
with child seeds. Each profile has one garden. Agents plant seeds, claim them,
log what happened and prove their checks from the CLI. People read the garden
beside their work, search it, move seeds across its board and judge the
checks.

## Sub-features

- `seed-plant`: plant a seed with a markdown body and numbered checks.
- `bed-routing`: with `garden_v2_enabled` on, bind a repository path or bare name to a bed. Root seeds and plots use the shell's current repository or the agent tool's session checkout. A new root delegation uses its destination checkout.
- `seed-edit`: change a body by exporting it, editing the file and saving it back. Each save is a numbered version, and `rollback` restores an earlier version as a new version.
- `plot`: plant a plot and its children in one move, with the plot's `part_of` and `discovered_from` and each child's `after` committed together. Children run in parallel unless a child waits for a sibling. attn refuses a payload with `blocks` and names `after`. attn refuses harvest and wither on a plot with open direct children. When the last child closes, attn leaves a ringing plot note, and the close command prints a line that names the plot. The plot keeps its state.
- `seed-tend`: claim a seed. A seed has one tender at a time.
- `seed-moves`: park, harvest, wither and replant. Repeating a move keeps the state and rings nobody. A different closing reason becomes a note. Every move prints who it rang and writes one `move` entry on the log, carrying the reason or the park's comment. A repeated move writes no entry.
- `harvest-when-merged`: arm a seed to harvest itself when its pull request merges. Name the pull request by url, or use the session's single open pull request. Clear the harvest condition to take the arming back.
- `seed-remind`: set a reminder on a seed with `--in` or `--at` and a message. When it comes due, attn posts the message to the seed's mailbox, and the tender reads it as a notice in the inbox. A seed holds one reminder, and a new one replaces it. `--clear`, harvest, wither and the post itself clear it.
- `seed-standby`: a seed's tender puts it on standby with a note that says what to do next, and the session closes, unless `--stay` keeps it open. A standby that would close the session refuses while the seed has unread mail or the session holds an open ask ([asks.md](asks.md) `ask-keeps-session-open`). `--in`/`--at` also set the seed's reminder to that time with the note as its message; `--clear` ends standby and leaves the reminder. Seed mail (a reminder, a message to the seed's id, an ask answer, a PR watch update addressed to the seed) then resumes the closed session tender as itself, or starts a session for the crew member that tends the seed, and delivers the mail with the note. A session that can compact compacts its conversation first, as `attn agent close --self --compact` does ([agent-launch.md](agent-launch.md) `close-compact`); any other closes plainly, and a crew member's session stays open. The profile setting `garden.tender_resume` (`any`, `watches`, `off`) decides which mail resumes a session, and **Settings → Agents and models → Seeds on standby** sets it. `docs/internal/inbox.md` (Starts and resumes) holds the rules.
- `standby-until`: the user picks "Standby until…" and a time in an agent's snooze menu, and attn types a prompt into that session asking its agent to run `seed-standby` with `--at` that time, planting a seed first when it tends none.
- `seed-notes`: the seed's log. It holds the notes that people and agents write and the `move`, `link`, `edit`, `answer` and `authorization` entries that attn writes when a seed changes. A handoff note primes the next tender. `--kind` keeps one kind of entry.
- `seed-show`: the first read prints the header, which names the seed's authorization and who set it when the seed has one. It then prints, in order, the bookmark, the newest entries, a pointer to an older handoff, edges with discovered seeds folded, the outline of the plot the seed is part of with a `--section` hint, a plot's open children as a board with closed ones folded into one line, checks and artifacts, and the body last. `ls --plot <plot>` lists every child of a plot, closed ones included.
- `seed-authorization`: set, clear or print the user's instructions for a seed's task, meaning the steps agents take beyond the project's guidance and the steps they stop before, from the CLI or the seed's page. A change by someone other than the live tender is typed into the tender as the user's message. The page and `show` say who set or cleared the words, when, and whether that change was typed into the tender. [delegation.md](delegation.md) drives the CLI side.
- `seed-section`: `show --section <heading|id>` prints one part of a body: the section under a heading, matched exactly or by the start of the heading, or every item that starts with an id like D3, each under its heading. attn refuses an unknown or ambiguous part and lists the parts.
- `seed-since`: every `show` and `notes` read prints a bookmark. `--since <bookmark>` returns only the entries saved after the bookmark, on the seed and every seed below it.
- `seed-checks`: what a seed must prove: report, confirm, reject, uncheck and reopen.
- `seed-watch`: follow a seed and its children. attn sends a seed update to the seed's current tender, to the tender of any plot that covers the seed, and to the seed's watchers. It sends the update after a ringing note or check move and after every state move. A covering tender needs no watch, and the coverage ends with the claim.
- `seed-edges`: blocks, part-of and discovered-from links. A link or unlink writes a `link` entry on both seeds, and a harvest that frees a seed writes `ready: <blocker> harvested` on the freed seed. `ready` lists what nothing blocks.
- `seed-slugs`: every `attn seed` verb, `attn delegate --seed` and `attn ask --seed` take a seed's slug where they take its id, within the caller's profile. `attn open` and `attn agent msg` take the id. attn refuses a slug that two seeds share and lists each match's id, state and title.
- `seed-artifacts`: files a seed owns, attached and detached.
- `seed-search`: keyword search across the profile's garden, closed seeds included.
- `garden-frame`: the garden as a drawer or fullscreen, with a list view and, fullscreen, a board view.
- `garden-board`: columns Ready, In progress, Parked and Closed. Moving a card moves the seed.
- `seed-tile`: a seed opened as a tile beside the agent that tends it.
- `seed-chip`: the seed a session tends, on its tile header, with its popover.
- `terminal-seed-card`: a seed id the garden knows is marked in a terminal, and hovering it shows the seed's card, which opens the seed as a tile or goes to the agent working it.
- `seed-export`: write a seed's body to a markdown file to read and annotate.
- `garden-v2`: behind the `garden_v2_enabled` experimental setting, curated project beds with repository auto-routing on root plantings and delegations, one-line status pulses, growing-seed close and standby guards, and bed and lens views across the drawer, fullscreen list, and board.
- `garden-guidance`: what attn tells its agents about the garden.

## How to get to it

### People

- ⌘⇧T on macOS and Ctrl+Alt+G on Linux (`board.open`, `native/crates/attn-app/src/keymap.rs`) open the garden in the frame it last had, the drawer at first. Pressed again, the key switches between the drawer and fullscreen. Escape closes the garden.
- Palette (`native/crates/attn-app/src/palette/commands.rs`): `garden-frame` ("Open the garden" while closed, "Open the garden fullscreen" while docked, "Move the garden to the sidebar" while fullscreen), and `show-tended-seeds` ("Show <agent>'s seeds"), offered while the active agent tends a seed or has a stake.
- Title bar: the garden icon `titlebar.garden`, labelled "Show the garden" or "Hide the garden" (`native/crates/attn-app/src/title_bar.rs`).
- In the garden (`native/crates/attn-app/src/garden/`): the search field, seed and plot rows, the trail back up a plot, the frame button ("Expand the garden" or "Return the garden to the dock"), and a seed's page with its Authorization section, its checks ("Confirm C1", reject, uncheck and reopen) and the buttons "Open as tile", "Resume", "Handover" and "Send to Chief". Arrow keys walk rows, and `/` returns to search.
- Elsewhere, "Open seed" on a blocked-resume notification (`native/crates/attn-app/src/notifications/mod.rs`), "Open in Garden" on an ask (`native/crates/attn-app/src/asks/view.rs`) and "Reveal in Garden" on a seed tile (`native/crates/attn-app/src/garden/tile.rs`) open the drawer at that seed.
- Fullscreen, the "Garden view" switch `garden.view` picks list or board (`native/crates/attn-app/src/garden/view.rs`). On the board, drag a card to a column or open the card's menu to park, harvest, wither or replant the seed with a reason (`native/crates/attn-app/src/garden/board.rs`).
- With `garden_v2_enabled` on (`native/crates/attn-app/src/garden/v2.rs`), wide fullscreen list and board views (at least 1160 pt) show the Beds rail (`garden.beds`, `garden.beds.add`, `garden.bed.all`, `garden.bed.<id>`, hover edit `garden.bed.<id>.edit`, `garden.bed.unassigned`, and `garden.bed.automations`). Narrower fullscreen windows and the drawer show bed chips (`garden.dock.beds`, `garden.dock.bed.*`, `garden.beds.add`). The fullscreen list search bar holds the `Now`, `Triage`, and `All` lens switch (`garden.lens.now`, `garden.lens.triage`, `garden.lens.all`), and the drawer header holds the `Now` and `All` toggle (`garden.dock.lens`). Search accepts `bed:<name|slug|id|unassigned|automations>` with `bed:` suggestions (`garden.search.bed.<id>`). `j` and `k` walk rows and cards, `garden.beds.add` and `.edit` open the bed dialog (`garden.bed-form`), and pressing `b` (or clicking `garden.head.bed` on a root seed page, or `seed-tile.<tile>.head.bed` on a root seed tile) opens the Assign bed picker (`garden.bed-picker`), resolving child seeds to their root plot and ignoring automation seeds.
- On an agent's tile header, the chip of the seed it tends opens the seed's popover (`native/crates/attn-app/src/desktop/seed_chip.rs`). The chip leaves out a seed title that repeats the session title, and a narrow tile cuts the title, then shows only the state icon.
- In a terminal, hovering a marked seed id shows its card `terminal.<runtime>.seed-card` (`native/crates/attn-app/src/desktop/seed_card.rs`). "Open as tile" opens the seed beside the terminal's agent. A button labelled with the agent's name ("Go to <agent>") goes to the seed's live tender, or else to the last session that tended it while that session is open, locally or on an outpost, as picking it in the sidebar does. The card leaves the button out when neither session is open or when that session owns the terminal. Escape closes the card.
- An agent's snooze menu: "Standby until…" `snooze.menu.standby` (`standby-until`, `native/crates/attn-app/src/sidebar/snooze.rs`). [queue-flow.md](queue-flow.md) says how to open the menu.
- Where people see what agents do: the tender and state on each row and card, a closed tender on standby as a dormant row under its dispatcher in `attn session list --tree` ([delegation.md](delegation.md)), the standby marker on a row and card of a seed on standby (its note, watched pull requests, reminder and a blocked resume in the row's tooltip, and a row's open blockers on its second line), notes on the seed's log, the chip on the agent's tile, and the seed tile `attn open` puts beside the agent.
- The phone app's Garden tab: read seeds, add notes, and park, harvest, wither or replant with a reason. [phones.md](phones.md) covers it.
- Their own shell: the same `attn seed` verbs agents use, below. Outside attn, `--profile <name|id>` picks the profile when there are several.

### Agents

- `attn seed` (`cli/attn/src/commands/seed/`): `plant` (with `--bed`), `plot`, `ls` (with `--plot` and `--bed`), `search`, `ready`, `show` (with `--since` or `--section`), `notes` (with `--since` and `--kind`), `edit` (an exported body on stdin, `-m -`, with `--note`), `rollback [<version>]`, `authorization [<words> | --clear]`, `remind (--in <duration> | --at <time>) -m <message> | --clear`, `tend`, `park`, `harvest` (with `--when-merged [<pr-url>]`, which takes the session's single open pull request when it gets no url, and `--when-merged --clear`, which takes the arming back), `wither`, `replant`, `note` (with `--handoff` and `--ring`), `pulse`, `bed ls|add|set|rm|assign`, `check add|edit|remove|restore|report|confirm|reject|uncheck|reopen`, `watch`, `unwatch`, `link`, `unlink`, `attach`, `detach`, `export`, `prime`, `guide`, `send-to-chief`.
- `attn seed bed add <name> --repo <path|name>` and `attn seed bed set <bed> --repo <path|name>` bind a repository. A relative path is resolved from the caller's working directory.
- [crew.md](crew.md) covers `send-to-chief`, which hands the seed to the chief. To hand a seed over, run `attn delegate --seed <id> --handover --cwd <path>`, which [delegation.md](delegation.md) covers. `attn seed handover` was removed and answers `seed: unknown command "handover"`.
- `attn open <seed-id>` opens the seed as a tile beside the caller. `attn ticket` prints the matching `attn seed` command (`cli/attn/src/commands/ticket.rs`).
- Prompts: the garden contract in every session's instructions, which `attn seed prime` also prints (`internal/prompts/content/garden.md`, then the CLI loop in `internal/prompts/content/garden-cli.md`, which a launch that carries attn's tools leaves out). The craft that `attn seed guide` prints (`internal/prompts/content/resources/seed-guide.md`). Ready seeds and their handoffs at session start (`internal/prompts/content/session/garden-ready.md`, `garden-row.md`, `garden-handoff.md`). The seed update an agent reads from its inbox (`internal/prompts/content/session/garden-update.md`). The request that "Standby until…" types into the session (`internal/prompts/content/session/standby-request.md`).

### Triggers

- attn sends the tender and watchers a seed update, which rings them, after a state move, a ringing note or check move, an armed or cleared harvest condition, or the close of a seed's last blocker (`internal/daemon/garden_nudges.go`). The rules are in `docs/internal/inbox.md`.
- A seed armed with `harvest --when-merged` harvests itself when its pull request merges, on the next pull request refresh (`internal/daemon/garden_harvest_when.go`).
- A seed with a reminder gets its message in the seed's mailbox on the first one-minute tick after the reminder's time (`internal/daemon/seed_reminder.go`).
- Seed mail for a seed on standby resumes its closed session tender, or starts a session for its crew member tender (`internal/daemon/inbox_delivery.go`, `internal/daemon/seed_resume.go`).

## Driving it

Preconditions:

- Use the baseline instance with its app, launched as [../SKILL.md](../SKILL.md) says. Then run `bridge wait '{"target":{"key":"home"}}'`. On Linux, run every command that reaches the app inside one `xvfb-run -a -s '-noreset -screen 0 1600x1000x24' bash -c '…'`.
- Widen the window with `bridge set_window_bounds '{"logicalBounds":{"x":0,"y":0,"width":1600,"height":1000}}'`, so a seed tile fits beside an agent instead of going to the shelf.
- Make the instance's notebook folder exist. Run `./attn journal append --entry "drive-attn setup"`: it prints `appended to journal/<date>.md`.
- Make a proof folder with `P=$(mktemp -d /tmp/drive-attn-garden.XXXX) && echo "export P=$P" >> $DRIVE_ENV`. Save `plot.json` in it: `{"title":"Recipe plot","body":"Two steps.","children":[{"title":"Draft step"},{"title":"Check step","after":["draft-step"]}]}`.
- Make an agent folder with `A=$(mktemp -d /tmp/drive-attn-garden-agent.XXXX) && echo "export A=$A" >> $DRIVE_ENV`. Save this fixture as `$A/.attn-mock-agent.json`:

```json
{"version": 1, "turns": [
  {"includes": "tend", "actions": [
    {"type": "capture", "name": "seed", "pattern": "(s-[a-z0-9]+)"},
    {"type": "attn", "args": ["seed", "tend", "{{seed}}"]}]},
  {"includes": "watch", "actions": [
    {"type": "capture", "name": "seed", "pattern": "(s-[a-z0-9]+)"},
    {"type": "attn", "args": ["seed", "watch", "{{seed}}"]}]},
  {"includes": "merge", "actions": [
    {"type": "capture", "name": "seed", "pattern": "(s-[a-z0-9]+)"},

  {"includes": "harvest", "actions": [
    {"type": "capture", "name": "seed", "pattern": "(s-[a-z0-9]+)"},

  {"includes": "arm", "actions": [
    {"type": "capture", "name": "seed", "pattern": "(s-[a-z0-9]+)"},

  {"includes": "clear", "actions": [
    {"type": "capture", "name": "seed", "pattern": "(s-[a-z0-9]+)"},
    {"type": "attn", "args": ["seed", "harvest", "{{seed}}", "--when-merged", "--clear"]}]}
```

`<seed>`, `<plot>`, `<card>`, `<own>` and `<merge>` below are the ids the plant commands print. `<terminal>` is the agent's terminal id from `wsctl list`.

- **Plant.** A person plants a seed with a check from their shell. Run `./attn seed plant "Garden drive" -m "Exercise the garden" --check "Shows in the garden"`. It prints `<seed>  garden-drive  Garden drive`, then `  C1  Shows in the garden`, and exits 0. Plant `"Garden drive followup"`: it lists the first seed under `similar open seeds` with its status, age and a wither hint for the new seed. Planting still succeeds when similar seeds exist. `plant --json` still prints the seed alone. `./attn seed show <seed>` shows `status planted` and C1 open.
- **Plant a plot.** Run `./attn seed plot -f $P/plot.json`. It prints the plot, then `draft-step` and `check-step` with their ids, followed by up to 3 similar open seeds across all the titles, each naming the new seed it resembles (`like <id>`). `plot --json` includes `similar`. `./attn seed ready --plot <plot>` lists only `draft-step`, and `./attn seed ls` shows the plot with `1 ready · 1 blocked`. A payload whose child has `"blocks"` exits 1 with `has "blocks", which plot payloads do not take` and the `after` to write instead, and plants nothing.
- **Route work into a bed.** Run `./scripts/test-go.sh --packages -v -run 'TestGardenV2(RoutesOutpostWorkFromTheCallersCheckout|AutoRoutesWorktreesSubdirsAndSymlinks|KeepsTheOutpostsRepository)' ./cmd/attnd ./internal/daemon`. The tests create beds and read back the saved membership after a CLI plant, plot or delegation. They cover relative bindings, local worktrees and symlinks, outpost shells that change repos, and an agent tool call with no working directory.
- **Nest a plot.** Run `./attn seed plant "Nest host"`, which prints `<host>`. Plot `{"title":"Inner plot","part_of":"nest-host","discovered_from":"garden-drive","children":[{"title":"Inner step"}]}` from stdin. `./attn seed show inner-plot` lists `part-of <host>` and `discovered-from <seed>`, `./attn seed show nest-host` lists `inner-plot` on its board, and `./attn seed notes nest-host --limit 1` reads `<inner-plot id> joined this plot`.
- **Slugs.** `./attn seed show garden-drive`, `notes`, `note`, `link`, `ready --plot recipe-plot` and the other verbs act on the seed that slug names. Plant `"Twin note"` twice: `./attn seed show twin-note` exits 1 with `the slug twin-note names 2 seeds in this profile`, one row per match with its id, state and title. A slug of a seed in another profile resolves as unknown. Driving that needs a second profile, which [profiles.md](profiles.md) sets up.
- **Search and link.** Run `./attn seed search drive`: it prints `2 seeds carry every word, 0 carry some — best first` and names `<seed>` with its status, last active age and the original line that matched. Word prefixes, stemming and identifier parts match. Partial matches follow full matches, and closed seeds remain findable. `--json` exposes `matched`, `partial` and each hit's `last_active`. `--limit` raises the default of 10. `./attn seed link <seed> discovered-from <plot>` prints the edge and `./attn seed unlink <seed> discovered-from <plot>` removes it.
- **Edit and roll back.** `./attn seed edit <seed> -m "Exercise every way in"` exits 1 with `edit takes an exported file`. Run `./attn seed export <seed> --out $P/seed.md`, change the body line under its first-line stamp to `Exercise every way in`, then `./attn seed edit <seed> -m - --note "drive edit" < $P/seed.md`: it prints `updated <seed>: body v2, 19 → 21 bytes`, and `./attn seed notes <seed> --kind edit` lists `body v2: 19 → 21 bytes — drive edit`. Saving the same file again exits 1 with `body changed before it could be saved`. `./attn seed rollback <seed>` prints `rolled <seed> back to v1 as v3`, `./attn seed rollback <seed> 2` restores v2 as v4, and `rollback <seed> 9` exits 1 listing `v1 through v4`.
- **Open and close.** The garden's body is the region "The garden" in both frames. Docked, `garden.frame-button` is named `Expand the garden`; fullscreen adds the dialog "The garden". Run `bridge key '{"chord":"mod+shift+t"}'` on macOS or `bridge key '{"chord":"mod+alt+g"}'` on Linux, where `mod+shift+t` opens a terminal: the garden opens in the frame it last had. Press the same chord again to move it between the dock and fullscreen: `bridge wait '{"target":{"role":"dialog","name":"The garden"}}'` answers fullscreen, and `bridge wait '{"target":{"key":"garden.frame-button","name":"Expand the garden"}}'` answers docked. Press Escape: `bridge wait '{"target":{"role":"region","name":"The garden"},"gone":true}'` answers. `bridge run '{"name":"board.open"}'`, the palette's `Open the garden`, and `bridge press '{"target":{"key":"titlebar.garden"}}'` open it too.
- **Search.** Run `bridge type '{"target":{"key":"garden.search.field"},"text":"Recipe"}'`: `garden.row.<plot>` answers, and a seed planted in another profile does not. `is:ready` and the other lenses narrow the list.
- **Walk a plot.** Press `garden.row.<plot>`: `bridge wait '{"target":{"key":"garden.head.title","name":"Recipe plot"}}'` answers and the children's rows show. Press Escape and open the garden again: it is still on the plot. Press `garden.frame-button`: fullscreen lays the walk out in columns, and pressing it again returns one level to the dock. `garden.trail.<n>` climbs back, and a long plot title is cut short of `garden.frame-button`.
- **Board and moves.** Plant a card for it: `./attn seed plant "Board drive"` prints `<card>`. Fullscreen, press `garden.view.board`: `garden.board.column.{ready,growing,parked,closed}` show the garden's top-level seeds as `garden.board.card.<seed>`. The board keeps its own walk: press `garden.board.drill.<plot>` to see a plot's children. Press the `<card>` card: its menu `garden.board.menu-of.<card>` opens. Press `garden.board.menu.park`, type a comment into `garden.board.compose.field` and press Enter: the field goes, and `./attn seed show <card> --json` is `parked` with the comment on its log. Harvest, wither and replant work the same, and a card dragged with `bridge drag` onto `garden.board.zone.<verb>` composes the same move. Press `garden.board.closed.reveal` to show or hide the closed seeds the column folds away. A closed plot with open work below it stays a card while folded. The board has no frame button: `garden.view.list` returns to the list, and Escape closes the garden.
- **An agent tends.** Run `wsctl add-session --cwd $A --agent claude --label garden-agent --id garden-agent`, find its terminal in `wsctl list`, and run `wsctl input --id <terminal> --text "tend <seed>" --enter`. `./attn agent peek garden-agent` shows `<seed> (garden-drive) is growing, tended by garden-agent`, and `./attn seed show <seed>` shows `status growing` and `tender garden-agent`.
- **The seed chip.** With `garden-agent` tending `<seed>`, `tile.<pane>.seed` is named `<title>, <State>. Open seed` and follows each move. `bridge hover` on it shows `tile.<pane>.seed.popover` with the latest note, `This agent reports to this seed.` and, once harvested, the outcome. The palette's "Show garden-agent's seeds", first while the agent is active, pins the same list. Pressing the chip opens the seed tile beside the agent: `bridge state '{"of":"desktops"}'` holds a `tile_kind` `seed` tile whose `tile_session_id` is `garden-agent`.
- **Watch and ring.** Run `wsctl input --id <terminal> --text "watch <plot>" --enter`: peek shows `watching <plot> and its descendants`. From the shell, run `./attn seed note <seed> -m "ring check" --ring`. It prints `rang garden-agent`. Thirty seconds after the last `wsctl input`, `./attn agent peek garden-agent` shows `📬 You have unread items in your attn inbox.`, with the rest of the line wrapped below it. `./attn agent inbox --session garden-agent` prints ``🔔 <seed> moved: note.added. Read what changed with `attn seed show <seed> --since <N>`.``, and that command lists the ring-check note. A second ringing note before the inbox is read joins the same update. The update keeps its `<N>`.
- **Artifacts.** Run `echo proof > $P/proof.txt` and `./attn seed attach <seed> --path $P/proof.txt --copy`. It prints `copy $P/proof.txt`, `to $HOME/attn-notebook-<name>/seeds/<seed>/proof.txt` with both paths written out, and `markdown target proof.txt`. Change `$P/proof.txt` and attach it again: the seed's file is replaced and the output adds `replaced the seed's earlier proof.txt`. Attaching the file unchanged once more is a no-op. `./attn seed detach <seed> --path proof.txt --to $P/proof-back.txt` moves it back out, and refuses a destination that exists.
- **Checks from the CLI.** Run `./attn seed check add <seed> -m "Survives a restart"`: attn numbers it and prints `C2 added on <seed> (garden-drive) · checks 0 of 2 confirmed · 2 open`. `./attn seed check add <seed> C1 -m "again"` is refused, naming C3 as the next free id, and `echo "Survives a daemon restart" | ./attn seed check edit <seed> C2 -m -` reads the statement from stdin. Run `echo proof > $P/proof2.txt` and `printf 'seen in the garden\n\nopened it twice\n' | ./attn seed check report <seed> C1 -m - --evidence $P/proof2.txt --evidence https://example.test/run`: it prints `C1 reported on <seed> (…) · attached proof2.txt`, and `./attn seed show <seed>` lists the summary line under C1 with `detail in its note · proof2.txt, https://example.test/run`, while `./attn seed notes <seed> --limit 1` holds the detail. ## Contexts

- **Durability across restarts**: seeds, logs, checks and artifacts are the daemon's records and come back after any restart. An unread seed update stays in the recipient's inbox, and attn withdraws it when that session stops tending or watching the seed.
- **Linux**: `attn seed` works the same where the daemon and CLI run on Linux. `board.open` is Ctrl+Alt+G there, because Ctrl+Shift+T opens a terminal (`native/crates/attn-app/src/keymap.rs`).
- **Outposts**: an agent on an outpost runs `attn seed` against the home's garden. For bed routing, the checkout path comes from the machine holding the checkout.
- **Profiles**: a seed belongs to the profile that planted it, for life. Lists, links, children, claims and delegations stay in that profile, and attn refuses another profile's seed by name. Inside attn the session picks the profile. Outside attn, `--profile` does when there are several.
- **Performance and idle cost**: when the garden holds more seeds than the app keeps, the board says "The garden holds N seeds; this board has M (every open seed and the newest closed).", and the list says the same of its panel. `native/crates/attn-app/tests/wire/garden/scale.rs` covers a large garden. Nothing measures an open garden's idle cost. When a change touches the garden's rendering, check for repaints with `docs/internal/perf-testing.md`.
- **Harnesses**: every harness drives the garden with the same `attn seed` verbs and reads the same garden prompts. A seed update rings the tender in the tender's own harness. A shell never gets a ring.
- **Keyboard and native input**: `board.open`, the palette, arrows, `/` and Escape reach the garden and its rows, and a card's open menu takes arrows and Enter.
- **Compatibility across versions**: a later version reads today's seeds, through the store's garden migrations. `attn ticket` answers with its replacement. `attn seed handover` was removed and is an unknown command.
- **Accessibility**: the search field names its active answer as its active descendant while it has answers, and a tile's pinned seed list names its picked seed, so VoiceOver reads each as ↑ and ↓ move.

## Gotchas

- `tend`, `watch` and arming with `harvest --when-merged` need a session. From a plain shell they exit 1 ("the user never claims a seed; run it from an attn session, or assign it to a crew member: attn seed tend <id> --for <name>", "watching is for a live attn session", "needs a session to track the pull request"). Drive them through the mock agent. `tend --for <name>` assigns the seed to a crew member, which is another entrypoint.
- The tender, sessions above the tender in the delegation chain, and the profile chief can move a claimed seed without `--force`. A member's claim lasts across the member's sessions. A session's claim lapses when the session ends and returns when the session resumes. Other actors need `--force`. A shell with no live source session has no standing. Standing and forced moves print their move entry, which names who forced and who held the seed, and the recipients.
- On a fresh instance, `attn seed attach` fails with `notebook root ... no such file or directory` until the notebook folder exists. The journal append in the preconditions creates it.
- A new check report clears the verdict. Report first, then confirm.
- Typing through `wsctl input` delays rings by 30 seconds. A `rang <session>` reply only says who will get the update. The proof is the 📬 line in that agent's terminal.
- An ordinary note does not ring. Only a note with `--ring` rings, as do state moves and the other events in `docs/internal/inbox.md`.
- `board.open` opens the garden in the frame used last, and fullscreen keeps its list or board view across relaunches. A run that opens fullscreen is not a bug.
- `harvest --when-merged` with no url takes the session's one open pull request. With no open pull request it exits 1 with `has no open pull request; pass the url`, and with two or more it lists their urls and asks which url to use. A merged pull request does not count, so the no-url step runs before the merge.
- `harvest --when-merged` fires on the next pull request refresh, not when the mock GitHub changes. Wait for `status harvested`. `wsctl refresh-prs` does not hurry the harvest.
- Seed ids are random. Take them from the `plant` output or `--json`, never from an earlier run.
- The list shows open seeds, and a closed plot while a seed at any depth below it is open, at the root and inside a plot. `is:` filters leave that rule out, and the closed toggle counts only the closed seeds the list hides. The board's folded Closed column keeps such a plot's card. To read a harvested child from there, search `<id> is:any`, or open its plot and include closed work.
- `seed show` pads its labels to the widest row, so `status planted` above stands for the label and its value, not their spacing. A wait loop matches `"status": "harvested"` in `--json`, or a pattern that allows any spacing.
