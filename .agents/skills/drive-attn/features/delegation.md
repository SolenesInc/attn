# Delegation

One agent starts another on a seed, from any harness to any harness, as a full
session the user can open and steer. Every delegation has a seed. Either the
dispatcher gives a brief, and attn plants a seed from it, or the dispatcher
names an existing seed. The delegate tends that seed as its stake, reads the
seed when the delegate starts, and reports there. A role sets the
instructions, harness, model and effort for one type of work. The user keeps
the roles, and agents choose among them. In a handover, a seed and its claim
pass to a fresh agent, and the previous agent keeps running.

## Sub-features

- `delegate-brief`: start a delegate on new work. The brief becomes the delegate's seed. When the dispatcher has a stake, that seed is part of the stake.
- `delegate-seed`: start a delegate on an existing seed nobody active tends.
- `handover`: a new session takes over a seed and its claim, with a note. The previous agent keeps running.
- `roles`: the user's roles, their alternatives and the fallback, kept in revisions with history and rollback.
- `workflow-skill`: "Add Attn roles" or `attn delegate roles install` adds attn's own roles and installs the attn-workflow skill that those roles use. While workflow skills are enabled, the daemon refreshes them at startup, when you save an executable setting, when you save delegation preferences, and when a role launches. Every way of saving preferences counts: the app, a CLI commit, and a rollback. Reading settings does not touch the skill files.
- `delegate-placement`: the delegate opens at the end of the row on the dispatcher's desktop, or on a named desktop, without changing what the user sees.
- `delegate-checkout`: the machine, folder and Git checkout the delegate works in.
- `delegation-status`: a stable request id to check or retry a delegation whose answer was lost.
- `delegation-chain`: the dispatcher, peers and delegates of a session, as a card you walk with the keyboard.
- `jump-to-dispatcher`: go from a delegate to the session that started it.
- `seed-continue`: Resume and Handover on a seed's page.
- `delegation-guidance`: what attn tells dispatchers and delegates, including the plan sign-off before dispatch and independent design candidates.

## How to get to it

### People

- ⌘⇧↑ (`session.orchestrator`, `native/crates/attn-app/src/keymap.rs`) goes to the dispatcher of the agent on screen.
- ⌘I (`session.details`; Ctrl+Shift+I on Linux) pins the delegation chain of the agent on screen, or its pull requests when it has no chain. [pull-requests.md](pull-requests.md) covers those.
- Palette (`native/crates/attn-app/src/palette/commands.rs`): `show-delegation-chain` ("Show delegation chain"), offered while an agent is active.
- [desktops.md](desktops.md) covers moving an agent with its delegates, from the palette or by dragging the agent's sidebar row with ⌥ held.
- The chain trigger on the agent's tile header, which names the role, opens the delegation chain card under the pointer, and a press pins it. On a sidebar row the trigger shows at rest, the card opens when you point at the row, and pressing the trigger pins the card (`native/crates/attn-app/src/desktop/chain.rs`). Pointing at an agent's id in a terminal opens the same card there. A card under the pointer takes no key but Escape, which closes it and still reaches the terminal, and ⌘I, which pins it on the agent it picks. A pinned card holds the keyboard and its edge takes the accent: ↑ ↓ Home End walk the chain, ← goes to the picked agent's dispatcher and → to its first delegate, Enter opens the picked agent, Tab switches to the agent's pull requests when the card hangs from a tile header and the agent has one, and ⌘I or Escape closes the card and gives the terminal the keyboard back. The foot names only the keys that work as the card stands.
- The card leads with the picked agent: its face, its whole name, its role, harness and outpost, its state and how long it has held it, what it is doing, and its seed, pull request and oldest open ask as buttons, which S, P and A press on a pinned card. The card of a closed agent, which an id in a terminal opens ([terminals.md](terminals.md)), instead offers Resume, its ledger row and its seed, which R, L and S press, and Enter resumes it. Under a rule, the tree names the agents, unless the chain shows only one: the picked row is tinted, and "here" marks the agent whose chain it is while another is picked. Each row shows what its agent needs from the user, "wants approval", "waiting for you" or a count of asks, before the role's mark. A delegate's row leaves out the start of the name it shares with its dispatcher, as "-terms" under "attn--sweep". The foot counts the agents that need the user, unless Tab has somewhere to go. In the sidebar, the row the card opened from is outlined and the picked agent's row is lit.
- The card keeps a delegate that closed on standby as a dormant row under its dispatcher, named with "on standby" and what it waits for, and Enter or a press on that row opens its seed in a tile beside the dispatcher. A dispatcher whose only delegate is on standby keeps its chain, and a live delegate of an agent on standby stays under that agent's dormant row.
- A seed's page in the garden: "Resume" and "Handover", with the handover form that asks "What should the new agent know?", the working folder, the Git checkout and the agent (`native/crates/attn-app/src/garden/continuation.rs`, `native/crates/attn-app/src/garden/handover.rs`).
- **Settings → Delegation** (`native/crates/attn-app/src/settings/delegation.rs`): the roles table and its switch, each role's alternatives, the fallback "Anything else", delete with Undo, and "Add Attn roles". "Add Attn roles" also installs the attn-workflow skill for each available harness: `~/.claude/skills` for Claude Code, `~/.agents/skills` for Codex, and the `skill_dirs` a plugin harness declares.
- Where people see and steer what agents do: the delegate is a full session in a tile on its dispatcher's desktop, with the delegate's role on the tile header and the seed the delegate tends on the tile's seed chip. People type into the delegate like any agent.
- Their own shell: `attn delegate --source-session <id>` and `attn delegate roles`, below.

### Agents

- `attn delegate` (`internal/catalog/content/delegate.yaml`, run by `internal/daemon/commands_delegate.go`; the CLI waits for the operation in `cli/attn/src/commands/delegate/present.rs`): `--brief`, `--brief-file` or `--seed`. `--handover` with `-m`. `--authorization`. `--cwd` with `--reuse-checkout`, `--new-worktree`, `--branch`, `--existing-branch`, `--from`, `--worktree-path` and `--allow-worktree-reuse`. `--host`. `--role`, `--choice`, `--fallback`, `--agent`, `--model`, `--effort`. `--name`, `--desktop`, `--priority`, `--yolo`, `--request-id`, `--source-session`, `--profile`.
- `attn delegate status <request-or-operation-id>` (`internal/daemon/commands_delegate.go`).
- `attn delegate roles` (`internal/catalog/content/delegate.yaml`, run by `internal/daemon/commands_delegate_roles.go`): with no command, it prints the catalog agents choose from. The commands are `show`, `history`, `install`, `add`, `set`, `copy`, `rm`, `enable`, `disable`, `apply`, `rollback`, each with `--json`.
- Agent tools: with `agent_tools_enabled` on, an agent calls the same commands over `/mcp` as `delegate`, `delegate_status`, `delegate_roles`, `delegate_roles_show` and so on. `delegate` waits up to 20 s for the delegate's first turn and answers with the operation, still `preparing` when the wait ran out, with the folder-trust question in its `progress` when the delegate is stopped there (`delegateToolBound` in `internal/daemon/commands_delegate.go`); a relative `cwd` resolves against the folder the session started in. Each answers what `--json` prints. The CLI's text comes only to the CLI, which asks for it with the internal arg `render`.
- `attn session list --tree` nests live sessions, and each closed agent on standby as a dormant row, under their dispatchers, so a live delegate of an agent on standby stays under that agent's dormant row (`internal/daemon/commands_session_tree.go`).
- `attn seed handover` is gone: it answers `seed: unknown command "handover"`. `attn delegate --seed <id> --handover --cwd <path>` replaces it.
- Prompts: every session's instructions carry the delegation boundary (`internal/prompts/content/delegation-boundary.md`). The delegate's opening names the delegate's seed and the seed's checks, including the shared checks of the seed's plot, or says that the seed has none. When the seed has an authorization, the opening ends with it and the acting rule that follows it (`internal/prompts/content/delegation/identity.md`, `opening.md`, `seed.md`, `seed-checks.md`, `seed-no-checks.md`, `authorization.md`, `authorization-from-user.md`, `authorization-rule.md`). The role's execution guidance and the catalog text are in `internal/prompts/content/delegation-preferences/`. `attn skill --reference delegation`s are `internal/prompts/content/skills/attn/references/delegation.md`, `delegated-agent.md` and `delegation-roles.md`, and its `delivery.md` covers both repository delivery flows. The attn-workflow skill tells a Pathfinder how to hand off a plan and when to run prototypes or independent candidates, and tells an Orchestrator how to delegate Builders (`internal/prompts/content/skills/attn-workflow/SKILL.md`, `references/planning.md`, `references/prototype.md`, `references/orchestration.md`). Without a daemon, `attn prompts show attn-workflow-skill` lists the skill and its references and `attn prompts render attn-workflow-skill planning` prints one ([agent-guidance.md](agent-guidance.md)).

## Driving it

Preconditions:

- Use the baseline instance with its app, launched as [../SKILL.md](../SKILL.md) says. On Linux, run every command that reaches the app inside one `xvfb-run -a -s '-noreset -screen 0 1600x1000x24' bash -c '…'`.
- Make a proof folder with `P=$(mktemp -d /tmp/drive-attn-delegation.XXXX) && echo "export P=$P" >> $DRIVE_ENV`.
- Make a delegate folder outside Git with `D=$(mktemp -d /tmp/drive-attn-delegate.XXXX) && echo "export D=$D" >> $DRIVE_ENV`, and save this fixture as `$D/.attn-mock-agent.json`:

```json
{"version": 1, "turns": [
  {"includes": "Your assignment", "actions": [
    {"type": "capture", "name": "seed", "pattern": "seed `(s-[a-z0-9]+)`"},
    {"type": "attn", "args": ["seed", "note", "{{seed}}", "-m", "read my assignment"]}]}
]}
```

- Make a dispatcher folder with `A=$(mktemp -d /tmp/drive-attn-dispatcher.XXXX) && echo "export A=$A" >> $DRIVE_ENV`, and save this fixture as `$A/.attn-mock-agent.json`. Each turn takes the delegate folder from the prompt:

- **Roles from the shell.** Run `./attn delegate roles`. On the baseline it prints `No delegation roles available.` and points at **Settings → Delegation**. Run `./attn delegate roles add drive --name "Drive" --agent codex --model mock-agent-1 -m "drive-attn"`, then `./attn delegate roles enable`. - **The other role commands.** Run `./attn delegate roles copy drive drive2 --name "Drive two"`, `./attn delegate roles set drive2 --description "second"`, `./attn delegate roles add drive2/fast --when "speed matters" --model mock-agent-1`, then `./attn delegate roles show drive2`: it prints `Drive two (drive2)`, the description and `alternative drive2/fast "fast"` with `when: speed matters`. `./attn delegate roles disable drive2` makes `./attn delegate roles show` mark the row `off` and count `1 of 2 roles offered to agents`. `enable drive2` turns the role back on. `./attn delegate roles rm drive2/fast` and `rm drive2` remove them, and `./attn delegate roles rollback` prints `revision <n> restores revision <n-2>` and brings `drive2` back. Remove `drive2` again. Export with `./attn delegate roles show --json > $P/roles.json` and run `./attn delegate roles apply $P/roles.json`: it prints a revision with `no changes`. The command refuses an export older than the live table with `the table changed after revision <n>; export it again`. Finish with `./attn delegate roles set --fallback --agent codex --model mock-agent-1`: `fallback: no model chosen → codex mock-agent-1`.
- **Roles in Settings.** `bridge run '{"name":"ui.openSettings"}'` opens `settings-dialog`. Press `settings.nav.delegation`. ## Contexts

- **Durability across restarts**: a delegation operation, its request id and its seed are the daemon's records. `attn delegate status` reads them after a restart, and a retry with the same `--request-id` returns the accepted operation instead of starting another operation. A delegation that a restart interrupts finishes on the same session once the daemon is back. Delegates come back like any session.
- **Linux**: `attn delegate` works the same where the daemon and CLI run on Linux. `session.orchestrator` is Ctrl+Alt+O there (`LINUX` in `native/crates/attn-app/src/keymap.rs`).
- **Outposts**: a delegation starts on the dispatcher's machine unless `--host` names an outpost, or `home`. attn checks paths on the target machine. attn refuses a delegation to an unknown or unreachable host before it accepts the delegation. After a home restart, an accepted operation waits for its outpost, and its status names the host. attn judges checkout sharing per machine.
- **Profiles**: the delegate, its seed and its desktop belong to the dispatcher's profile. `--desktop` takes only desktops of that profile. Outside attn, `--profile` picks the profile when there are several.
- **Performance and idle cost**: an open delegation chain card must not repaint while idle. The `native-delegation-chain` scenario drives the card.
- **Harnesses**: any harness delegates to any harness. `--agent` picks the delegate's harness, `--model` takes a model id exactly as the harness lists it, such as `openai/gpt-5.5`, and a role's choice pins harness, model and effort. Without a role, `--model` is required. `default` asks for the harness's own model.
- **Keyboard and native input**: ⌘⇧↑, ⌘I and the palette reach the chain with no pointer. A pinned card takes the arrows, Home, End, Enter, Tab, S, P, A and Escape, and R and L on a closed agent's card. Under a resting pointer the same keys are the user typing, so they reach the terminal. A focused text field or web page keeps ⌘I ([shortcuts.md](shortcuts.md)). A placed delegate does not take the keyboard: the dispatcher keeps focus.
- **Compatibility across versions**: retired flags answer with their replacement: `--ticket`, `--confirm`, `--plot`, `--worktree`, `--repo`, `--no-worktree`, `--preferences-revision` and the two flags that once chose a desktop. A delegate keeps the role it launched with when the role is later changed or deleted.
- **Flow**: `--priority` puts the delegate's owed turns first in queue flow. The chain trigger shows on queue sidebar rows and desktop sidebar rows alike.
- **Accessibility**: the pinned delegation chain keeps focus while the arrows walk it, and names the picked agent as its active descendant, so VoiceOver reads each agent as the arrows reach it. A chain of one agent has no row to name.

## Gotchas

- A single `bridge hover` on `tile.<leaf>.role` or `sidebar.session.<id>.chain` right after a press or a key does not open the card. A second `bridge hover` at the same point does. A real pointer sends many moves, so hover again before you wait for the card, and keep the first attempt in the proof.
- `attn delegate status` with an id no request or operation has, such as one the daemon refused before accepting it, answers `sql: no rows in result set` (seed `name-missing-request-attn-delegate-status`, s-9fw162).
- Without `--role` or `--fallback`, `attn delegate` exits 2 with `--model is required`. Every delegation needs `--cwd`. A relative path starts at the caller's directory, which for the mock agent is its session folder.
- From a plain shell there is no source session. Pass `--source-session <id>`, or `--agent` with `--model`, or the daemon refuses with `source inheritance is unavailable`.
- The daemon refuses a seed that an active session tends unless you pass `--handover`, and the refusal names the tender. Delegating the dispatcher's own stake also needs `--handover`.
- `attn delegate` returns once the delegate's first turn starts (for Sigma or another server-linked harness, once its server first reports the conversation), or after 90 seconds with a `first_turn_unconfirmed` line on stderr. At that point attn rings a note on the seed with the screen. For a Claude or Codex stopped at its folder-trust question, the note and the line name the question, and the session reads `waiting_input` with reason `folder_trust_question` from 10 seconds after launch. A delegate whose fixture matches nothing in its opening still starts, but writes no note. Match on `Your assignment`, which every delegate's opening carries.
- A Claude delegate into a repository whose `origin` a session in the profile started a conversation in, on any machine, gets the main repository's trust key in that machine's `.claude.json` and asks nothing. In any other repository the question stays. The config must already exist, or attn writes nothing.
- Inside Git, a delegation needs one complete checkout form. attn refuses a delegation into a checkout that an active session uses, until you pass `--allow-worktree-reuse`. Keep the delegate folder outside Git to drive the rest.
- `--desktop 7` creates a missing numbered desktop. Rerunning the recipe on the same instance finds the desktop already there, which is expected.
- The seed page fills the handover's folder and agent from a live tender. With the tender gone or the tender's folder removed, the form asks for a working folder and an agent ("required without a source session"). Resume shows only when the closed session's conversation can come back. For a session that ran on an outpost the page does not ask the outpost: it offers Resume with `directory_state: unchecked` and refuses at the press if the directory or conversation is gone, or shows `directory_state: unreachable` while the bridge is down, with Resume dimmed on the page. Tab reaches the dimmed button, which shows `resume_reason` while it has focus or the pointer. On a seed a crew member claims, or a seed whose last session was a member's, Resume starts or focuses the member instead of reopening that session, and says so when the member is retired. The same holds for work assigned with `attn seed tend <id> --for <name>` from a session or by the user. The page offers Resume before the member has a session. After the member tends and parks the seed, Resume goes back to the member, never to the session that assigned the seed. Without the app, `wsctl seed-continuation --seed <seed>` prints what the page offers and `wsctl seed-resume --seed <seed>` presses Resume. The mock writes a resumable conversation only with `"resumable": true` in its fixture, and then under the harness home. The harness home is your real `~/.claude` or `~/.codex` unless `ATTN_TOOL_HOME` named a scratch folder when the daemon started. Drive Resume of a closed session only with that folder set, never against the real home.
- A reused `--request-id` returns the first operation with that id. Pick a new id per run, or expect the old result.
- `attn delegate roles add <role> --builtin ...` needs "Add Attn roles" or `attn delegate roles install` once. Without the install, the add is refused with `role <role> is an Attn role and needs the attn-workflow skill; install it with attn delegate roles install, or Add Attn roles in Settings > Delegation`. Custom roles need `--name`.
- On a named instance, "Add Attn roles" and `attn delegate roles install` are both refused with `attn-workflow installation is disabled for instance "<name>"; saved preferences were not changed`, so a built-in role cannot be added there. A named instance never writes skills into your harness homes ([agent-guidance.md](agent-guidance.md)). Drive roles there with `--name`, as above.
- One `attn delegate` runs one choice of a role. For a design choice that is costly to reverse, the agent presenting the options may propose independent candidates: one Prototyper delegation per distinct model among the role's choices that fit, each `attn delegate --role prototyper --choice <id>`, with the default counted among them. Several Prototyper delegations from one dispatcher on one task are independent candidates, not a bug. When the fitting choices share one model, the agent starts one delegation and says so. Working but wrong: candidates started before the user agreed to them, or a delegated Prototyper starting candidates of its own.
- A Pathfinder presents the plan and waits for the user's choice even when the request included execution. The Pathfinder dispatches without waiting only when the user said, before the plan existed, to dispatch without reviewing it. In that case the Pathfinder records its understanding and the user's instruction as notes on the plan seed and names that seed in its reply. Working but wrong: dispatching after a request that merely included execution, such as "just do it", or skipping the review with no note on the plan seed.
- Working but wrong: `attn delegate roles` lists nothing while the table is turned off, even with roles saved. `show` still lists them. The role's name shows on the delegate's tile header, but a role deleted later stays on delegates that launched with it.
